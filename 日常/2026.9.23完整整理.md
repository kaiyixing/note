## 五、MinIO 部署与排障

### 5.1 镜像拉取失败（ImagePullBackOff）

**问题现象**
```bash
kubectl get pods -n vending | grep minio
# minio-598d54b5f4-clhdd   0/1   ImagePullBackOff   2d23h
```

**原因**：`imagePullPolicy: Always` 强制从 quay.io 拉取镜像，但代理 `192.168.1.7:10808` 不可达。

**解决方案**
```bash
# 修改为使用本地镜像（node01 已有该镜像）
kubectl patch deployment minio -n vending \
  -p '{"spec":{"template":{"spec":{"containers":[{"name":"minio","imagePullPolicy":"IfNotPresent"}]}}}}'

kubectl rollout restart deployment/minio -n vending
```

**验证**
```bash
kubectl get pods -n vending | grep minio
# minio-74598f479-r797g   1/1   Running
```

### 5.2 Service 类型修改与端口固定

**原始配置**（ClusterIP，仅集群内可访问）
```yaml
type: ClusterIP
```

**修改为 NodePort + 固定端口**
```yaml
type: NodePort
ports:
  - name: api
    port: 9000
    targetPort: 9000
    nodePort: 30009       # 固定端口
  - name: console
    port: 9001
    targetPort: 9001
    nodePort: 30010       # 固定端口
```

**为什么固定端口**：NodePort 不指定时，每次重启可能分配不同端口，导致 URL 失效。

## 六、图片无法显示问题

### 6.1 问题诊断
浏览器无法显示图片，但 MinIO 服务正常。

### 6.2 根因分析
ConfigMap 中的 `MINIO_ENDPOINT` 使用集群内地址，浏览器无法访问。

```yaml
# 原始配置（有问题）
MINIO_ENDPOINT: "http://minio.vending:9000"
```

### 6.3 解决方案

**步骤1：修改 ConfigMap**
```bash
kubectl patch configmap vending-config -n vending \
  -p '{"data":{"MINIO_ENDPOINT":"http://172.16.1.22:30009"}}'
```

**步骤2：更新数据库中的图片 URL**
```sql
UPDATE product 
SET image_url = REPLACE(image_url, 'http://minio.vending:9000', 'http://172.16.1.22:30009')
WHERE image_url LIKE 'http://minio.vending:%';
```

**步骤3：重启 Pod 使配置生效**
```bash
kubectl delete pod -n vending -l app=vending-server
# 或
kubectl rollout restart deployment/vending-server -n vending
```

## 七、图片上传失败问题

### 7.1 问题诊断
上传图片返回错误，MinIO 控制台也无法访问。

### 7.2 原因分析
MinIO Bucket 默认权限是私有，外部无法直接访问和上传。

### 7.3 解决方案

**设置 Bucket 为公共读写**
```bash
# 设置 minio CLI 别名
kubectl exec deploy/minio -n vending -- sh -c \
  'mc alias set local http://localhost:9000 minioadmin minioadmin1234'

# 设置 bucket 权限
kubectl exec deploy/minio -n vending -- sh -c \
  'mc anonymous set public local/vending-images'
```

**验证**
```bash
# 上传测试文件
kubectl exec deploy/minio -n vending -- sh -c \
  'echo "test" | mc pipe local/vending-images/test.txt'

# 通过 NodePort 访问
curl http://172.16.1.22:30009/vending-images/test.txt
# 返回: test
```

## 十三、关键文件说明

### 13.1 配置文件位置
| 文件 | 用途 |
|------|------|
| `~/vending/k8s/05-minio.yaml` | MinIO Deployment + Service |
| `~/vending/k8s/06-vending-server.yaml` | 包含 ConfigMap（MINIO_ENDPOINT） |
| `~/vending/k8s/05-minio-init.sh` | MinIO 初始化脚本 |

### 13.2 MinIO 完整配置
```yaml
# 05-minio.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: minio
  namespace: vending
spec:
  replicas: 1
  selector:
    matchLabels:
      app: minio
  template:
    metadata:
      labels:
        app: minio
    spec:
      containers:
      - name: minio
        image: quay.io/minio/minio:RELEASE.2025-04-22T22-12-26Z
        imagePullPolicy: IfNotPresent          # 关键：使用本地镜像
        args:
        - server
        - /data
        - --console-address
        - ":9001"
        ports:
        - containerPort: 9000
        - containerPort: 9001
        env:
        - name: MINIO_ROOT_USER
          valueFrom:
            secretKeyRef:[REDACTED] minio-secret
              key: root-user
        - name: MINIO_ROOT_PASSWORD
          valueFrom:
            secretKeyRef:[REDACTED] minio-secret
              key: root-password
        volumeMounts:
        - name: minio-data
          mountPath: /data
        readinessProbe:
          httpGet:
            path: /minio/health/live
            port: 9000
          initialDelaySeconds: 10
          periodSeconds: 10
      volumes:
      - name: minio-data
        persistentVolumeClaim:
          claimName: minio-pvc
---
apiVersion: v1
kind: Service
metadata:
  name: minio
  namespace: vending
spec:
  type: NodePort                          # 外部可访问
  selector:
    app: minio
  ports:
  - name: api
    port: 9000
    targetPort: 9000
    nodePort: 30009                       # 固定端口
  - name: console
    port: 9001
    targetPort: 9001
    nodePort: 30010                       # 固定端口
```

## 十六、关键经验总结

| 问题 | 解决方案 |
|------|----------|
| ImagePullBackOff | 设置 `imagePullPolicy: IfNotPresent` |
| 图片显示空白 | 修改 ConfigMap 中 `MINIO_ENDPOINT` 为外部地址 |
| 数据库旧图片无法显示 | SQL UPDATE 批量替换 URL |
| 上传图片失败 | 设置 Bucket 权限为 public |
| NodePort 端口变化 | 在 yaml 中显式指定 `nodePort` |
| 配置未生效 | 重启 Pod（删除 pod 让 deployment 重建） |
| Rancher 密码遗忘 | 从 `bootstrap-secret` 获取 |
| 接口返回乱码 | 用 `file` 检查编码 + MySQL 指定 `--default-character-set=latin1` |
| Pod 日志排查 | `kubectl logs deploy/xxx -f` 实时跟踪 |
| 服务本地调试 | `kubectl port-forward` 映射到 localhost |
| 接口无响应 | 用 `kubectl get endpoints` 确认后端pod就绪 |
