## 一、RKE K8s 集群管理

```bash
rke up --config cluster.yml          # 启动/更新 K8s 集群
rke config --name cluster.yml        # 查看集群配置
```

* 15 次：9 次 `rke up` + 4 次查看配置
* RKE（Rancher Kubernetes Engine）一键建集群，`cluster.yml` 是集群定义文件

## 二、Helm 包管理

```bash
helm repo add jetstack https://charts.jetstack.io
helm repo add rancher-latest https://releases.rancher.com/server-charts/latest
helm repo update
helm install cert-manager jetstack/cert-manager --namespace cert-manager --create-namespace --version v1.17.1
helm install rancher rancher-latest/rancher --namespace cattle-system --set hostname=172.16.1.22.sslip.io --set replicas=1 --set bootstrapPassword=admin123456!
helm uninstall cert-manager -n cert-manager
helm registry login harbor.opschef.tech
```

* 装 cert-manager（证书自动续期）+ Rancher（K8s 管理面板）
* `--set` 覆盖 values，`bootstrapPassword` 是 Rancher 首次登录密码
* `helm registry login` 登录私有镜像仓库（Harbor）拉 chart

## 三、K8s kubectl（按子命令）

```bash
# get（75 次，最高频）
kubectl get pods -A -o wide
kubectl get pods -n vending -l app=vending-server
kubectl get svc
kubectl get endpoints vending-server -n vending
kubectl get configmap vending-config -n vending -o yaml | grep DB_URL

# apply / delete（25+10 次）
kubectl apply -f 03-mysql.yaml
kubectl delete pod xxx -n xxx

# exec（21 次）
kubectl exec -it -n vending deploy/mysql -- mysql -uroot -proot1234 -e "..."
kubectl exec -it -n vending deploy/vending-server -- env | grep DB_URL
kubectl exec -it -n vending deploy/vending-server -- sh -c "curl -s http://localhost:8080/api/cabinet/list | head -c 300"

# describe / logs（各 10/9 次）
kubectl describe pod xxx -n xxx
kubectl logs deploy/vending-server -f

# port-forward（7 次）
kubectl port-forward -n vending svc/vending-server 8080:8080

# rollout / config（各 6 次）
kubectl rollout status deploy/xxx -n xxx
```

* **apply 闭环**：`vim yaml` → `apply` → `get pod` → `get svc` → `describe`（异常时）
* **exec 验证** 比改 yaml 更快确认配置是否下发
* **describe** 是排查 pod 问题第一手信息（事件、容器状态、资源）

## 四、Docker（按子命令）

```bash
# login（12 次）
docker login harbor.opschef.tech -u admin -p <密码>

# info（9 次）
docker info | grep -i mirror        # 看镜像加速配置

# pull / build（5/4 次）
docker pull mysql:8.0
docker build -t vending-server:1.0.0 .
docker build -t vending-web:1.0.0 .

# save / push 镜像（离线传输）
docker save vending-web:1.0.0 vending-admin:1.0.0 -o /tmp/frontend.tar
docker save vending-server:1.0.0 -o /tmp/vending-server.tar
```

* **Harbor 私有仓库** harbor.opschef.tech 是镜像中心
* **save + scp + load** 是离线传镜像到无网节点的标准链路（配合下面 scp 部分）
* **build 三个镜像**：vending-server（后端）、vending-web / vending-admin（前端）

## 五、systemctl 服务管理

```bash
systemctl restart docker        # 12 次（最高频）
systemctl daemon-reload         # 8 次（改完 systemd unit 必做）
systemctl status docker         # 6 次
systemctl stop docker           # 5 次
systemctl enable docker         # 4 次（开机自启）
systemctl stop containerd       # 关容器运行时
systemctl stop docker.socket    # 关 socket 激活
```

* 改 `/etc/docker/daemon.json`（镜像加速/日志轮转）后：`daemon-reload` + `restart docker`
* 17 次涉及 `/etc/docker/daemon.json`：改 `"registry-mirrors"`、`"max-size"`（日志轮转）

## 七、远程传输（scp / ssh）

```bash
scp /tmp/frontend.tar root@192.168.1.19:/tmp/
scp /tmp/frontend.tar root@192.168.1.20:/tmp/
scp /tmp/vending-server.tar root@192.168.1.19:/tmp/
scp root@172.16.1.25:/root/.local/share/mkcert/rootCA.pem /tmp/
ssh root@172.16.1.22 / .23 / .24 / .25
ssh-copy-id
```

* **离线传镜像链路**：master `docker save` → `scp` 到节点 → 节点 `docker load`
* `ssh-copy-id` 一次性配免密登录
* 节点 IP 分布：172.16.1.22（master）/ .23 / .24 / .25（K8s 节点），192.168.1.19 / .20（Ansible 管理目标）

## 八、Ansible 部署与调试

```bash
ansible-playbook playbook/site.yml
vim playbook/site.yml
vim roles/web/tasks/main.yml
vim roles/web/handlers/main.yml
vim roles/web/templates/index.html.j2
ansible web -m command -a "cat /var/www/html/index.html"
ansible web -m command -a "ls -l /var/www/html/index.html /etc/httpd/conf.d/welcome.conf"
sudo vi /etc/httpd/conf/httpd.conf
```

* **部署循环**：改 yaml → `ansible-playbook` 跑 → `curl` 验证 → 再改
* **ad-hoc 验证**：`ansible <group> -m command -a "<cmd>"` 不进 playbook 直接查远端
* **template 不生效**：本地 `cat` 模板 vs 远端 `ansible -m command -a "cat ..."` 对比

## 十二、命令组合模式速查

| 模式                                     | 示例           | 用途          |
| -------------------------------------- | ------------ | ----------- |
| `rke up --config`                      | 一键建集群        | RKE 标准操作    |
| `helm repo add + install`              | 装 chart      | 标准 Helm 流   |
| `vim + apply + get`                    | K8s 变更闭环     | 标准 K8s 流    |
| `docker save + scp + docker load`      | 离线传镜像        | 无网节点标准链路    |
| `systemctl daemon-reload + restart`    | 改配置生效        | 改配置必做       |
| `yum install docker-ce <版本>`           | 装指定版本 docker | 跨 el8/el9   |
| `ansible -m command -a "cat"`          | ad-hoc 查远端   | 比全量重跑快      |
| `kubectl exec -- sh -c "cmd1 \| cmd2"` | 容器内管道        | 跑复杂命令       |
| `curl -s URL -o /tmp/x + file`         | 编码排查         | 判断真实编码      |
| `crictl ps \| grep`                    | 底层容器         | kubelet 卡死时 |
| `tmux new -s` + 长任务                    | 断线不丢         | 长任务标准挂法     |

## 十三、关键经验

1. **RKE + Helm** 是 K8s 集群标准部署组合：rke 建集群，helm 装组件
2. **离线镜像链路**：`docker save` → `scp` → `docker load`，无网节点唯一解
3. **systemd 改配置**：`daemon-reload` 不能省，否则 unit 文件不生效
4. **docker 不同版本装不同节点**：el8/el9 用不同版本号，注意区分
5. **Harbor + mkcert + update-ca-trust**：私有仓库 + 自签证书完整链路
6. **Ansible ad-hoc command** 比 `debug: true` 全量重跑快
7. **K8s svc 无流量**：先看 endpoints，再看 selector/label
8. **port-forward + curl** 是集群内服务调试最高效闭环
9. **乱码先查 locale + `file`**，不要先怀疑业务逻辑
10. **长任务挂 tmux**：rke up、build 都断线不丢
11. **kubelet 异常用 `crictl`** 看底层容器，绕过 kubectl 卡死
12. **ping 测内外网**：github 测外网，harbor 测内网，定位网络问题范围
