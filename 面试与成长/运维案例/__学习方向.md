# 运维案例 — 学习方向

## 这个目录用来放什么

把**真实遇到的故障和问题**记录下来，形成自己的案例库。

## 一个案例模板

```markdown
# 故障标题

- **时间**：2025-01-01
- **影响范围**：XX 服务，影响 XX 用户
- **故障等级**：P0 / P1 / P2

## 故障现象
用户反馈...

## 排查过程
1. 先查什么（监控、日志）
2. 发现了什么（告警、错误信息）
3. 怎么定位到根因

## 根因分析
- 为什么发生

## 解决方案
- 临时修复（止血）
- 永久修复（治本）

## 后续改进
- 监控补充
- 流程改进
- 自动化告警
```

## 典型案例方向
- **系统类**：磁盘写满、OOM、内核参数导致问题
- **网络类**：DNS 解析异常、TCP 连接泄漏、丢包
- **应用类**：GC 导致卡顿、连接池耗尽、慢 SQL
- **K8s 类**：Pod 驱逐、节点 NotReady、CNI 网络问题
- **数据库类**：主从延迟、死锁、数据误删恢复

## 建立习惯
每次排完一个故障，花 15 分钟记下来。以后遇到类似问题，先翻自己的案例库。
