## 一、Pod Deep Dive（补完）

### 1. Init 容器重启行为

```yaml
spec:
  restartPolicy: Always   # Pod 级别，影响容器重启策略
  initContainers:          # 串行执行，全部成功后才启动 app 容器
  - name: init-db
    image: busybox
```

| restartPolicy | init 容器失败时 |
|---|---|
| `Always`（默认） | 重试（指数退避），已成功的 init 容器不重跑 |
| `Never` | Pod 进入 Failed 终态（Phase=Failed, Reason=Init:Error） |
| `OnFailure` | 同 Always（重试） |

**关键规则**：
- init 容器**串行执行**，前一个成功才跑下一个
- 成功的 init 容器不会因后续 init 失败而重跑
- init 容器全部成功后，应用容器才启动

### 2. Init 容器资源计算

```
Pod 有效资源 = max(所有 init 容器的 requests) + sum(所有应用容器的 requests)
```

- init 容器串行 → 取最大值
- app 容器并行 → 求和
- **口诀**：串行取 max，并行取 sum

### 3. Lifecycle Hooks

```yaml
spec:
  containers:
  - name: app
    lifecycle:
      postStart:      # 容器启动后异步执行，不阻塞主进程
        exec:
          command: ["/bin/sh", "-c", "echo started"]
      preStop:        # 容器终止前阻塞执行，跑完才收 SIGTERM
        exec:
          command: ["sleep", "5"]
```

| Hook | 触发时机 | 行为 | 失败后果 |
|---|---|---|---|
| **PostStart** | 容器 ENTRYPOINT 启动后 | 异步并行 | Hook 失败 → 容器被 kill |
| **PreStop** | 容器收到终止信号前 | 阻塞 | 超时后 SIGKILL |

#### terminationGracePeriodSeconds 与 preStop

```
kubectl delete pod
  → preStop 开始执行
  → terminationGracePeriodSeconds（默认 30s）是总超时
  → 超时后 SIGKILL 强制杀容器
```

**注意**：preStop 时间必须 < grace period，否则被截断。

### 4. 容器状态（Container States）

| State | 说明 |
|---|---|
| **Waiting** | 等待中（拉镜像、退避中） |
| **Running** | 正常运行 |
| **Terminated** | 已退出（exit code） |

常见 Waiting Reason：
- `CrashLoopBackOff` → 容器反复崩溃，kubelet 退避重试
- `ImagePullBackOff` → 镜像拉取失败
- `Init:Error` / `Init:CrashLoopBackOff` → init 容器失败

### 5. Phase vs Conditions（误解已纠正）

| | Pod Phase | Pod Conditions |
|---|---|---|
| 层级 | 粗粒度整体状态 | 细粒度独立状态 |
| 值 | Pending / Running / Succeeded / Failed / Unknown | PodScheduled / Initialized / ContainersReady / Ready |
| 示例 | Running ✅ | Ready=True/False |

**Running 是 Phase，不是 Condition。**

### 6. K8s YAML 通用骨架

```yaml
apiVersion: v1              # API 版本
kind: Pod                   # 资源类型
metadata:                   # 名字、标签、注解
  name: my-pod
  labels:
    app: web
spec:                       # 期望状态（核心）
  containers:               # app 容器列表
  - name: app
    image: nginx
    ports:
    - containerPort: 80
    resources:              # requests/limits
    volumeMounts:
  initContainers: []        # init 容器
  restartPolicy: Always     # Always / OnFailure / Never
  volumes: []               # 存储卷
status:                     # 实际状态（系统填充，只读）
```

## 二、Workload Controllers

### 5 种 Controller 总览

| Controller | 一句话 | 适用场景 |
|---|---|---|
| **Deployment** | 无状态应用，滚动更新/回滚 | Nginx、API Server |
| **ReplicaSet** | 维持 Pod 副本数（Deployment 的下层） | 一般不直接创建 |
| **StatefulSet** | 有状态应用，固定网络标识+存储 | MySQL、Redis、Kafka |
| **DaemonSet** | 每个节点跑一个 Pod | 网络插件、监控、日志 |
| **Job** | 跑一次到完成 | 数据迁移、批处理 |
| **CronJob** | 定时跑 Job | 备份、定时清理 |

### Deployment

```yaml
apiVersion: apps/v1
kind: Deployment
spec:
  replicas: 10
  strategy:
    type: RollingUpdate       # 默认策略
    rollingUpdate:
      maxSurge: 25%           # 超出期望的最大 Pod 数（百分比向上取整）
      maxUnavailable: 25%     # 允许不可用的最大 Pod 数
```

**滚动更新过程**：
- replicas=10, maxSurge=3, maxUnavailable=3
- Pod 总数范围：**7 ~ 13**
- 创建新 ReplicaSet 逐步扩容 + 旧 RS 逐步缩容
- `kubectl rollout undo deploy/webapp` 回滚

### StatefulSet

```yaml
apiVersion: apps/v1
kind: StatefulSet
spec:
  serviceName: web
  replicas: 3
  updateStrategy:
    type: RollingUpdate
    rollingUpdate:
      partition: 2       # 灰度更新
  volumeClaimTemplates:  # 自动创建 PVC
  - metadata:
      name: data
    spec:
      accessModes: ["ReadWriteOnce"]
      resources:
        requests:
          storage: 1Gi
```

**关键特性**：
- Pod 命名：`web-0`, `web-1`, `web-2`（ordinal index 固定）
- 网络标识：`web-0.web.default.svc.cluster.local`
- Pod 重启后名字不变

**Partition 灰度更新**：
```
partition = 2, replicas = 5
  web-4  web-3  web-2  |  web-1  web-0
  ──── 更新为新版 ──── | ── 保留旧版 ──
  ordinal >= partition  |  ordinal < partition
```

### DaemonSet

```yaml
apiVersion: apps/v1
kind: DaemonSet
spec:
  selector:
    matchLabels:
      app: node-exporter
  template:
    spec:
      containers:
      - name: node-exporter
        image: prom/node-exporter
```

**实现机制**：
DaemonSet Controller 通过 Informer 监听 Node 变化：
```
新节点加入 → API Server → Informer 通知 Controller → 创建 Pod（指定 nodeName）
节点删除 → Informer 通知 → 自动清理 Pod
```

**典型场景**：网络插件（Calico）、监控（Node Exporter）、日志（Fluentd）

### Job

```yaml
apiVersion: batch/v1
kind: Job
spec:
  backoffLimit: 4             # 重试上限（总共最多 1+4=5 次）
  activeDeadlineSeconds: 30   # 超时自动终止
  template:
    spec:
      restartPolicy: Never     # 仅支持 Never / OnFailure（不支持 Always）
      containers:
      - name: pi
        image: perl
        command: ["perl", "-Mbignum=bpi", "-wle", "print bpi(2000)"]
```

### CronJob

```yaml
apiVersion: batch/v1
kind: CronJob
spec:
  schedule: "*/5 * * * *"           # cron 格式
  concurrencyPolicy: Forbid          # Allow / Forbid / Replace
  startingDeadlineSeconds: 100       # 错过调度窗口后的等待上限
  successfulJobsHistoryLimit: 3      # 保留的历史 Job 数
  jobTemplate:
    spec:
      template:
        spec:
          restartPolicy: OnFailure
```
