## 教学约定（重要）

**给 kaiiyii 讲技术时，不要堆术语。**

- 他的症状是"学很久但不能领悟"，根因之一是**地基概念缺失**。任何一个新术语（控制面/数据面、调谐循环、声明式…）都要先拆开讲，再拿它讲模块。
- **类比优先**，且要挑他已有的强项做类比：
  - 网络 / 转发 / 代理类 → 用**路由器**（CPU 算路由 vs ASIC 查表转发）
  - 存储类 → 用 NFS/Ceph 相关经验（他的存储笔记标注 ★★★★☆）
  - 进程/资源类 → 用 Linux / systemd
- 讲解结构：**痛点 → 类比 → 图 → 判断标准（可复用的尺子）→ 排障视角**。
- 他偏好分阶段（Phase 1/2/3）落地，且希望获批后直接产出文件，不要停在讨论层。

## K8s 教学主线（已建立，后续沿用）

**调谐循环三件套**：拿到任何对象问三个问题——期望端是谁 / 现实端是谁 / 控制器有几个。

总纲见 `容器与编排/Kubernetes/Kubernetes 知识聚合索引.md` 第 2、3 节。
结论：11 个模块 = 10 次同一个循环 + 1 个拦截器（RBAC 是唯一的例外，属 apiserver 准入链路）。
推荐顺序（依赖优先，非大纲顺序）：存储 PV/PVC → 调度 → HPA → Ingress → NetworkPolicy，RBAC 随时可学。
