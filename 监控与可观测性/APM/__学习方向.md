# APM — 学习方向

## 核心概念
- **APM**（Application Performance Monitoring）：应用性能监控
- **三大支柱**：Metrics（指标）→ Tracing（链路）→ Logging（日志）
- **Trace**：一次请求的完整调用链
- **Span**：Trace 中的一个操作单元
- **采样**：全量采样 vs 头采样 vs 尾部采样

## 主流方案
| 方案 | 特点 |
|------|------|
| **SkyWalking** | 国产，Java 生态好，无侵入 |
| **Jaeger** | Uber 开源，云原生，与 OpenTelemetry 深度集成 |
| **Pinpoint** | 韩国 NAVER 开源，Java 字节码注入 |
| **OpenTelemetry** | 标准规范，不是 APM 系统，但可对接多种后端 |

## 实操清单
- [ ] 部署 OpenTelemetry Collector
- [ ] 在应用中加入 OpenTelemetry SDK（Java/Go/Python）
- [ ] 端到端链路查看（Span 详情、耗时分布）
- [ ] 定位慢调用（哪个服务、哪个 API 慢）
- [ ] 错误链路追踪（看失败的请求经过哪些服务）
- [ ] 采样策略配置（生产环境控制成本）

## 常见场景
- 用户说"接口 5 秒才返回"，哪里慢了？
- 微服务调用链中某个环节偶尔超时
- 新版本上线后，错误率上升，快速定位影响
