好，给一个完整的真实场景：**某个程序启动后闪退，没有日志，没有报错。**

### 1. 先看启动时发生了什么

```bash
strace -o /tmp/strace.log ./myapp
```

### 2. 分析日志

打开 `/tmp/strace.log`，长这样（简化版）：

```
execve("./myapp", ["./myapp"], [/* 48 vars */]) = 0
brk(NULL)                               = 0x55555556a000
mmap(NULL, 8192, PROT_READ|PROT_WRITE, MAP_PRIVATE|MAP_ANONYMOUS, -1, 0) = 0x7ffff7fce000
...
openat(AT_FDCWD, "libfoo.so", O_RDONLY|O_CLOEXEC) = -1 ENOENT (No such file or directory)
openat(AT_FDCWD, "/usr/lib/libfoo.so", O_RDONLY|O_CLOEXEC) = -1 ENOENT
write(2, "error: cannot open libfoo.so\n", 30) = 30
exit_group(1)                           = ?
+++ exited with 1 +++
```

问题清楚：**动态库没找到**，程序没法启动。`ENOENT` + `write(2, ...)` 说明它其实写了错误信息，但**写到了 stderr 而不是 stdout**，你跑的时候没重定向所以没看见。

### 更进阶：追踪网络服务为啥连不上

```bash
# -f 跟踪子进程，-e trace=... 只关注网络和文件操作
strace -f -e trace=network,openat,connect -s 1024 \
  -o /tmp/nginx.strace nginx
```

看输出：

```
[pid 1234] openat(AT_FDCWD, "/etc/nginx/nginx.conf", O_RDONLY) = 3
[pid 1234] bind(4, {sa_family=AF_INET, sin_port=htons(80)}, 16) = -1 EACCES
[pid 1234] write(2, "bind() to 0.0.0.0:80 failed (13:", ...) = 41
```

`EACCES` on bind 说明**没权限绑定 80 端口**（需要 root 或 `CAP_NET_BIND_SERVICE`），而不是配置语法错误。

### 再加一个性能排查

```bash
strace -c -p 12345 > /dev/null &
sleep 10
kill %1
```

输出统计：
```
% time     seconds  usecs/call     calls    errors syscall
------ ----------- ----------- --------- --------- ----------------
 45.23    0.452342          12       384           poll
 30.12    0.301234           5       612           write
 15.11    0.151123         150       100           read
  9.54    0.095432          95       100           openat
------ ----------- ----------- --------- --------- ----------------
100.00    1.000131                  1196         total
```

poll 占了 45% 时间，说明应用大量时间在**等待 I/O 就绪**（可能是不必要的 busy polling），write 调用 612 次频次很高，可能是日志写太频繁拖慢性能。

### strace 常用技巧总结

| 参数 | 作用 |
|------|------|
| `-o file` | 输出到文件，不干扰终端 |
| `-f` | 跟踪子进程（fork/clone） |
| `-e trace=<set>` | 只跟踪某类 syscall（`file`, `network`, `process`, `signal`, `read`, `write` 等） |
| `-s N` | 显示最多 N 字节的字符串内容（默认 32） |
| `-tt` | 带微秒的时间戳 |
| `-T` | 显示每个 syscall 耗时（微秒） |
| `-c` | 统计模式（汇总不是逐行） |
| `-p PID` | 附着到运行中的进程 |
| `-e read=<fd>` | 只看某个 fd 的 read 内容（很实用） |

---

### 什么时候不该用 strace

- **生产环境高并发服务**：strace 会使进程慢 **10~100 倍**，只适合开发/预发环境或低流量实例用 `-p` 短暂附着
- **CPU 密集场景**：系统调用很少，strace 抓不到有用信息，应该用 `perf` 或 `flamegraph`
- **已知道路**：日志或错误码已经足够定位问题时，不需要 strace
