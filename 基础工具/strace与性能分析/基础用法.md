## 1. 系统调用是什么

操作系统将 CPU 指令权限分为多个环（Ring）。Linux 使用两层架构：

- **用户态**（Ring 3）：应用程序运行的区域。不能直接访问硬件、操作内存页表、发送网络包。
- **内核态**（Ring 0）：操作系统内核运行的区域。能操作所有硬件资源。

当程序需要做"特权操作"时——比如打开文件、发送网络数据、分配内存——它通过**系统调用**（syscall）切换到内核态，让内核代劳。

```
应用程序 (用户态)
    │
    ├─ fopen() → 触发 openat 系统调用
    ├─ send()  → 触发 sendto 系统调用
    └─ malloc() → 触发 brk / mmap 系统调用
           │
           ▼
Linux 内核 (内核态) → 执行实际操作 → 返回结果
```

**strace 的工作原理**：它使用 `ptrace`（Process Trace）系统调用附着到目标进程。内核在每次系统调用进入和返回时通知 strace，strace 将参数和返回值记录下来。这个过程**不修改目标程序的二进制代码**，完全在操作系统层面完成。

因为 strace 拦截了每一次用户态 / 内核态切换，它会带来显著的性能开销（通常 10~100 倍变慢）。这是它的最大代价，也是为什么生产环境要谨慎使用。

## 2. 安装 strace

大多数 Linux 发行版预装了 strace。如果没有，按以下方式安装：

```bash
# Debian / Ubuntu
apt-get install strace

# RHEL / CentOS / Fedora
yum install strace
# 或
dnf install strace

# Arch Linux
pacman -S strace

# Alpine Linux
apk add strace

# 从源码编译
git clone https://github.com/strace/strace.git
cd strace
./bootstrap
./configure
make -j$(nproc)
make install
```

验证安装：

```bash
strace -V
# 输出示例: strace -- version 5.19
```

## 3. 输出格式详解

strace 的每行输出遵循这个格式：

```
[syscall名](参数...) = 返回值 <耗时>
```

逐段拆解：

### 3.1 系统调用名

```
openat(AT_FDCWD, "foo.txt", O_RDONLY) = 3
^~~~~~~
```

系统调用名与 Linux 内核函数名一致。常见的有 `openat`、`read`、`write`、`close`、`mmap`、`brk`、`poll`、`epoll_wait`、`connect`、`accept`、`sendto`、`recvfrom`、`futex`、`clone`、`execve` 等。

### 3.2 参数

括号内是传入参数，strace 会尽力将其解析为人类可读的形式：

- 文件路径：显示字符串内容
- 标志位：按位解析为名字组合（如 `O_RDONLY|O_CLOEXEC`）
- 套接字地址：解析为 `{sa_family=AF_INET, sin_port=htons(80)}`
- 内存地址：显示为十六进制（如 `0x7fff00001234`）
- 结构体指针：如果 strace 能识别，会显示结构体内容

### 3.3 返回值

等号后面的就是返回值：

```
openat(AT_FDCWD, "foo.txt", O_RDONLY) = 3    ← 成功，返回文件描述符 3
openat(AT_FDCWD, "noexist", O_RDONLY) = -1   ← 失败，返回 -1
```

- 正数或 0：调用成功
- -1：调用失败，此时 `errno` 跟在后面
- `=?`：被信号中断，返回值未知
- 部分调用（如 `mmap`）返回内存地址

### 3.4 错误码

失败时 strace 会同时输出符号名和描述：

```
openat(AT_FDCWD, "noexist", O_RDONLY) = -1 ENOENT (No such file or directory)
                                         ^~~~~~   ^~~~~~~~~~~~~~~~~~~~~~~~~~~~
                                         errno    含义
```

### 3.5 耗时

使用 `-T` 参数时，每行末尾的 `<>` 内显示该 syscall 的耗时（单位微秒）：

```
read(3, buf, 4096) = 4096 <0.000345>
                         ^~~~~~~~~
                         345 微秒
```

## 4. 参数分类速查

### 4.1 跟踪控制: `-e trace=`

#### 按调用名筛选

```bash
# 只跟踪特定系统调用（多个用逗号分隔）
strace -e trace=open,read,write,close ls

# 跟踪所有系统调用（默认）
strace -e trace=all ls
```

#### 按类别筛选（最实用）

strace 预定义了多个类别，每个类别覆盖一组相关的系统调用：

| 类别名 | 覆盖范围 | 常用场景 |
|--------|----------|----------|
| `file` | 文件操作：`openat`, `read`, `write`, `close`, `stat`, `unlink`, `rename`, `fcntl` 等 | 文件访问、配置读取、日志写入 |
| `network` | 网络操作：`socket`, `connect`, `bind`, `listen`, `accept`, `sendto`, `recvfrom`, `setsockopt` | 网络连接、端口绑定、数据收发 |
| `process` | 进程管理：`fork`, `clone`, `execve`, `exit`, `wait4`, `kill` | 进程创建、子进程调试 |
| `signal` | 信号操作：`signal`, `sigaction`, `sigprocmask`, `kill`, `rt_sigreturn` | 信号处理 |
| `ipc` | 进程间通信：`shmget`, `shmat`, `semop`, `msgget`, `msgsnd`, `msgrcv` | 共享内存、信号量、消息队列 |
| `desc` | 文件描述符操作：`read`, `write`, `close`, `fcntl`, `ioctl`, `dup`, `dup2` | FD 泄漏排查 |
| `memory` | 内存管理：`mmap`, `brk`, `mprotect`, `munmap`, `shmdt` | 内存分配分析 |
| `%stat` | 文件状态查询（不跟踪修改操作） | 低噪音检查 |
| `%wall` | (strace 5.0+) 只显示耗时超过一定阈值的调用 | 性能分析 |

```bash
# 只看文件操作
strace -e trace=file ls

# 只看网络操作（调试网络服务）
strace -e trace=network nginx

# 只看进程管理（调试 fork/clone 问题）
strace -e trace=process myapp

# 只看内存映射
strace -e trace=memory myapp

# 只看文件描述符操作（排查 FD 泄漏）
strace -e trace=desc myapp

# 只看超过 1ms 的调用（strace 5.0+）
strace -e trace=%wall -T myapp 2>&1 | awk -F'[<>]' '$2+0 > 1000 {print}'
```

#### 同时跟踪多个类别

```bash
# 文件 + 网络
strace -e trace=file,network myapp

# 进程 + 信号
strace -e trace=process,signal myapp
```

#### 排除某些调用

```bash
# 跟踪所有调用，但排除 brk 和 mmap
strace -e trace=all -e exclude=brk,mmap myapp
```

### 4.2 输出控制

#### `-o file`：输出到文件

默认 strace 输出到 stderr。用 `-o` 重定向到文件：

```bash
strace -o /tmp/strace.log ls
# 文件内容即为跟踪输出，终端干干净净
```

#### `-s N`：控制字符串显示长度

```bash
# 默认只显示前 32 字节
strace ls  # read(3, "hello world...", 4096) = 12

# 显示更多字节（看完整路径、数据内容）
strace -s 1024 ls

# 显示全部（可能输出巨大）
strace -s 0 ls  # 0 表示无限制
```

#### `-v`：详细模式（不缩写结构体）

strace 默认会缩写复杂的结构体。`-v` 禁止缩写：

```bash
# 默认：省略数组/长结构体
strace ls  # getdents64(3, /* 10 entries */, 4096) = 280

# 展开所有结构体
strace -v ls  # getdents64(3, [{d_ino=..., d_name="."}, {d_ino=..., d_name=".."}, ...], 4096) = 280
```

#### `-xx`：以十六进制显示字符串

```bash
# 默认：可打印字符直接显示，不可打印的转义
strace ls  # write(1, "file.txt\n", 9) = 9

# 全部十六进制（适合看二进制数据）
strace -xx ls  # write(1, "\x66\x69\x6c\x65\x2e\x74\x78\x74\x0a", 9) = 9
```

#### `-q`：安静模式（去掉 strace 自身的提示行）

```bash
# 默认会输出进程附着/分离信息
strace -p 1234
# strace: Process 1234 attached
# ...

# 去掉这些提示
strace -q -p 1234
```

#### `-qq`：更安静，连退出状态都不显示

```bash
strace -qq ls
```

### 4.3 时间戳

```bash
# -t：秒级时间戳（精确到秒）
strace -t ls
# 10:15:30 openat(AT_FDCWD, ".", O_RDONLY) = 3

# -tt：微秒级时间戳（精确到微秒）
strace -tt ls
# 10:15:30.123456 openat(AT_FDCWD, ".", O_RDONLY) = 3

# -ttt：Unix 时间戳（自 epoch 以来的秒数 + 微秒）
strace -ttt ls
# 1712345678.123456 openat(AT_FDCWD, ".", O_RDONLY) = 3

# -T：每个 syscall 的耗时（微秒）
strace -T ls
# openat(AT_FDCWD, ".", O_RDONLY) = 3 <0.000045>
```

组合使用最有用：

```bash
strace -tt -T ls
# 10:15:30.123456 openat(AT_FDCWD, ".", O_RDONLY) = 3 <0.000045>
#          ^^^^^^^^^^^                         ^^^^^^^^^
#          时间戳                              耗时
```

### 4.4 进程相关

#### `-p PID`：附着到运行中的进程

```bash
# 附着单个进程
strace -p 12345

# 附着多个进程
strace -p 12345 -p 12346 -p 12347
```

#### `-f`：跟踪子进程（fork/clone/vfork）

```bash
# 跟踪父进程和所有子进程
strace -f myapp

# 输出会包含 [pid NNNN] 前缀
# [pid 1234] execve("./worker", ...) = 0
# [pid 1235] openat(AT_FDCWD, "data.txt", ...) = 3
```

#### `-F`：跟踪 vfork 的子进程（现在已经包含在 -f 里，很少单独用）

#### `-ff`：每个子进程单独输出文件

与 `-o` 配合使用，每个进程的输出写到不同文件：

```bash
# 主进程: /tmp/strace.log
# 子进程1: /tmp/strace.log.1234
# 子进程2: /tmp/strace.log.1235
strace -ff -o /tmp/strace.log myapp
```

#### 进程状态输出

```
[pid  1234] +++ killed by SIGTERM +++    ← 被信号杀死
[pid  1235] +++ exited with 0 +++        ← 正常退出
[pid  1236] --- SIGPIPE {si_signo=SIGPIPE, ...} ---  ← 收到信号
```

### 4.5 统计模式

#### `-c`：汇总统计（不输出每行调用）

```bash
# 程序执行完成后输出统计表
strace -c ls

# 对运行中的进程统计一段时间
strace -c -p 12345
# 然后 Ctrl+C 中断，显示这段时间内的统计
```

输出格式：

```
% time     seconds  usecs/call     calls    errors syscall
------ ----------- ----------- --------- --------- ----------------
 45.23    0.452342          12       384           poll
 30.12    0.301234           5       612           write
 15.11    0.151123         150       100           read
  9.54    0.095432          95       100           openat
------ ----------- ----------- --------- --------- ----------------
100.00    1.000131                  1196         total
```

各列含义：

| 列 | 含义 |
|----|------|
| `% time` | 该 syscall 占总执行时间的百分比 |
| `seconds` | 该 syscall 累积耗时（秒） |
| `usecs/call` | 每次调用的平均耗时（微秒） |
| `calls` | 调用次数 |
| `errors` | 失败次数 |
| `syscall` | 系统调用名 |

#### `-C`：同时输出统计和逐行跟踪

```bash
# 既打印每行调用，结束时也显示统计汇总
strace -C ls
```

#### `-w`：按耗时排序（strace 4.26+）

默认 `-c` 的统计按调用名排序。`-w` 改为按总耗时从高到低排序，更容易一眼识别瓶颈：

```bash
strace -c -w myapp
# 最耗时的 syscall 排在最前面
```

## 5. 描述符内容跟踪: `-e read=` / `-e write=`

只看某个文件描述符（fd）的读写内容，不输出其他干扰：

```bash
# 只看 fd=3 的 read 内容
strace -e read=3 myapp

# 只看 fd=1 (stdout) 的 write 内容
strace -e write=1 myapp

# 多个 fd
strace -e read=3,4,5 myapp

# 范围语法
strace -e read=3-5 myapp
```

输出示例（看 fd=3 读入了什么）：

```
read(3, "{\n  \"name\": \"myapp\",\n  \"version\"", 4096) = 34
```

这在调试**配置解析**或**协议交互**时特别有用。比如你想知道程序从配置文件里读到了什么，或者往网络 socket 写了什么数据。

## 6. 信号跟踪

strace 默认会显示进程收到的信号（但不是全部）：

```bash
# 跟踪信号相关的系统调用
strace -e trace=signal myapp
```

输出格式：

```
--- SIGTERM {si_signo=SIGTERM, si_pid=1234, si_uid=1000} ---
             ^^^^^^^^  ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
             信号名     信号详细信息（谁发的、发的进程 PID）
```

常用信号对照：

| 信号 | 数字 | 常见来源 | strace 中的表现 |
|------|------|----------|----------------|
| SIGHUP | 1 | 终端断开、重启请求 | `--- SIGHUP ... ---` |
| SIGINT | 2 | Ctrl+C | `--- SIGINT ... ---` |
| SIGQUIT | 3 | Ctrl+\ | `--- SIGQUIT ... ---` |
| SIGILL | 4 | 非法指令 | `--- SIGILL ... ---` |
| SIGABRT | 6 | abort() 调用 | `--- SIGABRT ... ---` |
| SIGBUS | 7 | 内存对齐错误 | `--- SIGBUS ... ---` |
| SIGFPE | 8 | 浮点异常 | `--- SIGFPE ... ---` |
| SIGKILL | 9 | kill -9 | 进程直接消失，strace 无输出 |
| SIGSEGV | 11 | 段错误（空指针解引用） | `--- SIGSEGV ... ---` |
| SIGPIPE | 13 | 写已关闭的管道 | `--- SIGPIPE ... ---` |
| SIGTERM | 15 | kill 默认信号 | `--- SIGTERM ... ---` |

## 7. 错误码速查

strace 输出中最常见的是 `-1` 加一个 `E` 开头的错误码。下面是出镜率最高的错误码及其含义：

| 错误码 | 数字 | 含义 | 典型场景 |
|--------|------|------|----------|
| **ENOENT** | 2 | 文件或目录不存在 | 动态库没找到、配置文件路径不对 |
| **EACCES** | 13 | 权限不足 | 无读/写/执行权限，或 bind 低端口无 root |
| **EAGAIN** | 11 | 资源暂时不可用（非阻塞操作重试） | socket 读无数据、非阻塞 connect 未完成 |
| **EWOULDBLOCK** | 11 | 同 EAGAIN（数值相同） | 同上 |
| **EINTR** | 4 | 系统调用被信号中断 | 慢速 IO（read/write）被信号打断 |
| **EIO** | 5 | 输入输出错误 | 磁盘坏道、设备故障 |
| **EBADF** | 9 | 文件描述符无效 | 重复关闭、操作已关闭的 fd |
| **ENOMEM** | 12 | 内存不足 | fork 失败、内存分配失败 |
| **EFAULT** | 14 | 指针地址无效 | 传入的缓冲区指针不在用户空间 |
| **EEXIST** | 17 | 文件已存在 | 创建文件时目标已存在 |
| **ENOTDIR** | 20 | 不是目录 | 路径中的某一级不是目录 |
| **EISDIR** | 21 | 是目录 | 对目录进行了文件操作 |
| **EINVAL** | 22 | 无效参数 | 传入的参数不合法 |
| **EMFILE** | 24 | 进程已打开太多文件 | 文件描述符泄漏（FD 泄漏） |
| **ENFILE** | 23 | 系统文件表满 | 系统级 fd 耗尽 |
| **EPIPE** | 32 | 管道断裂 | 写一个没有读端的管道/socket |
| **EROFS** | 30 | 只读文件系统 | 尝试写只读挂载的文件系统 |
| **ENOSPC** | 28 | 设备无空间 | 磁盘满了 |
| **ESPIPE** | 29 | 非法定位 | 在管道上使用 lseek |
| **ECONNRESET** | 104 | 连接被对端重置 | 对方主动关闭连接 |
| **ECONNREFUSED** | 111 | 连接被拒绝 | 端口未监听 |
| **ECONNABORTED** | 103 | 连接中断 | 对方异常断开 |
| **ETIMEDOUT** | 110 | 连接超时 | 网络不通 |
| **EHOSTUNREACH** | 113 | 主机不可达 | 路由不通 |
| **ENETUNREACH** | 101 | 网络不可达 | 网线断了/网络不通 |
| **EADDRINUSE** | 98 | 地址已使用 | 端口被占用 |
| **EADDRNOTAVAIL** | 99 | 地址不可用 | 绑定的 IP 不存在 |

### 快速判断思路

```
open / connect / bind 返回 -1
│
├─ ENOENT  → 文件不存在 → 检查路径
├─ EACCES  → 权限不足 → 检查文件权限 / 是否 root
├─ EMFILE  → FD 用完 → 检查 FD 泄漏
├─ EADDRINUSE → 端口占用 → netstat -tlnp
├─ ECONNREFUSED → 端口未监听 → 检查服务端
├─ ECONNRESET → 连接被重置 → 检查对端是否异常退出
├─ ETIMEDOUT → 连接超时 → 检查网络 / 防火墙
└─ ENOSPC  → 磁盘满 → df -h
```

## 8. 常见陷阱与注意事项

### 8.1 strace 附着的权限

```bash
# 非 root 用户只能跟踪自己的进程
strace -p 1234  # OK，如果 1234 是你的进程

# 跟踪别人的进程需要 root
sudo strace -p 1234  # 1234 是 root 或其他用户的进程

# Docker 容器内需要 --cap-add=SYS_PTRACE
docker run --cap-add=SYS_PTRACE myapp strace -p 1
```

### 8.2 strace 本身的安全风险

- strace 使用 `ptrace`，理论上被跟踪的进程可以检测到（检查 `/proc/self/status` 中的 `TracerPid`）
- 某些恶意软件会检测并改变行为
- 不要在生产环境长期附着，会严重影响性能

### 8.3 输出量爆炸

```bash
# 一个简单的 ls 就可能产生 100+ 条输出
# 一个 web 服务每秒可能产生 10 万+ 条系统调用记录
```

解决办法：

```
优先使用 -e trace= 缩小范围
优先使用 -c 汇总模式而非逐行输出
使用 -o 写文件避免终端成为瓶颈
用 grep / awk 后处理过滤关键信息
```

### 8.4 对目标进程的影响

- strace 会给每个 syscall 增加约 1~10 微秒的延迟（ptrace 上下文切换成本）
- 高频率 syscall 的程序（如 Nginx、Redis）受影响最大
- 对于大量小 `read`/`write` 的程序，吞吐量可能下降 90%+
- 时间敏感的程序（音视频、实时控制）在 strace 下行为可能完全改变

### 8.5 多线程进程的跟踪

```bash
# 多线程程序使用 -f 才能跟踪所有线程
# 但输出会非常混乱，建议：
# 1. 用 -c 看汇总
# 2. 用 -e trace= 缩小范围
# 3. 用 -ff 分文件输出
strace -ff -e trace=network -o /tmp/threads myapp
```

### 8.6 strace 不是魔法

- strace 看到的是 syscall 级别，不是函数级别（函数级别用 `ltrace`）
- strace 看不到 CPU 内部计算（用 `perf`）
- strace 看不到堆内存内部状态（用 `valgrind` / `AddressSanitizer`）
- strace 看不到网络包内容细节（用 `tcpdump` / `Wireshark`）

### 8.7 setuid 程序的跟踪限制

setuid 二进制文件启动时，如果 strace 不是 root 运行，内核会**丢弃 setuid 位**以防止提权。使用 root 或 `sudo` 可以绕过。

### 8.8 卸载 strace

```bash
# strace 退出后会自动恢复目标进程，不需要额外操作
# 但如果 strace 被 kill -9，目标进程可能受到影响
# 建议用 Ctrl+C 正常终止
```
