## 第一章：Vim 哲学与入门

### 1.1 Vim 为什么值得学

大多数编辑器（VS Code、Sublime、Notepad++）遵循同一套交互模型：你敲键盘，字符出现在光标位置。这很自然，因为它模拟了打字机。

Vim 走了另一条路。它不把你当成打字员，而把你当成 **编辑器**。

这个区别是关键。打字员的工具是「往纸面上放字」。编辑者的工具是「操作文本」——删除、复制、移动、替换、重构。Vim 的整套设计都围绕后者展开。

**Vim 的核心优势：**

| 特性 | 说明 |
|------|------|
| **模态编辑** | 不同模式做不同事，按键复用率高，无需 Ctrl/Alt 组合 |
| **操作符 + 动作** | 像语言一样组合命令，表达能力极强 |
| **零鼠标** | 手不离开主键盘区，速度提升明显 |
| **无处不在** | 几乎所有 Unix/Linux 系统都预装 vi，服务器上没有 GUI 编辑器 |
| **可编程** | VimScript 和 Lua 让你定制一切 |
| **文本对象** | 操作「一个单词」「一对括号」「一个段落」是原生概念 |

三天难受，三周适应，三个月回不去。这不是玄学，是肌肉记忆形成的客观周期。

### 1.2 模态编辑（Modal Editing）

普通编辑器只有一种模式：你按 `a`，屏幕上出现 `a`。

Vim 有 **多种模式**，每种模式下按键的含义不同。

**四种主要模式：**

| 模式 | 名称 | 进入方式 | 典型操作 |
|------|------|----------|----------|
| **Normal**（正常模式） | 默认模式 | `Esc` 从任何模式返回 | 移动、删除、复制、粘贴 |
| **Insert**（插入模式） | 打字模式 | `i` `a` `o` `s` 等 | 输入文字 |
| **Visual**（可视模式） | 选择模式 | `v` `V` `Ctrl-v` | 选中文本块 |
| **Command-line**（命令行模式） | 执行命令 | `:` `/` `?` | 保存、查找、替换、配置 |

**核心规则：大部分时间待在 Normal 模式，进入 Insert 模式只做短暂的文本输入，输完立刻返回 Normal。**

新手最常见的错误是一直待在 Insert 模式里，用方向键移动光标。这违背了 Vim 的设计——如果你在 Insert 模式下用方向键，说明你该按 `Esc` 然后用 `h/j/k/l` 移动。

### 1.3 vimtutor

Vim 自带交互式教程，这是**所有人**的起点。

```bash
# 终端输入
vimtutor
```

大约 30-40 分钟，覆盖最基本的操作。完成后你就能用 Vim 编辑文件了。建议做两遍，中间隔一周。

> **注意**：如果系统提示 `vimtutor` 命令不存在，安装 Vim 即可（见下一节）。Neovim 用户可以用 `nvim +Tutor` 或 `:Tutor`。

### 1.4 安装

**Linux（Debian/Ubuntu）：**

```bash
sudo apt install vim        # 传统 Vim
sudo apt install neovim     # Neovim（较新版本）
```

**macOS：**

```bash
brew install vim
brew install neovim
```

**Windows：**

```powershell
# 方法一：官方安装包
# 访问 https://github.com/vim/vim-win32-installer/releases
# 或 https://github.com/neovim/neovim/releases

# 方法二：使用 winget
winget install vim.vim
winget install Neovim.Neovim

# 方法三：使用 chocolatey / scoop
choco install vim neovim
scoop install vim neovim
```

安装后打开终端执行 `vim` 或 `nvim`，看到 Vim 界面就成功了。退出方式：`:q`（`:q!` 强制退出，不保存）。

### 1.5 第一次启动

```bash
vim hello.txt
```

你会看到 Vim 界面，光标停在左上角。你现在在 **Normal 模式**。

试试这些操作：

1. 按 `i` —— 进入 Insert 模式，左下角显示 `-- INSERT --`
2. 输入一些文字
3. 按 `Esc` —— 回到 Normal 模式
4. 按 `:wq` 然后回车 —— 保存并退出

如果出了问题，按 `Esc` 几次确保你在 Normal 模式，然后按 `:q!` 回车（不保存强制退出）。

## 第二章：基础移动与编辑

### 2.1 移动：在文本中快速导航

Vim 的移动命令是效率的基石。理解它们不是背键位，而是理解**移动的原子操作**可以（也应当）与其他操作组合。

#### 基本方向移动

```vim
h       左移一个字符
j       下移一行
k       上移一行
l       右移一个字符
```

**为什么不是方向键？** 方向键在标准键盘上需要移动右手，打乱节奏。`hjkl` 就在主键盘区，手不用离开打字位置。

> **练习**：用 `vimtutor` 里的练习文件，强制自己只使用 `hjkl` 移动，不用方向键。第一周会很别扭，第二周开始形成肌肉记忆。

#### 单词级移动

```vim
w       跳到下一个单词的词首
W       跳到下一个单词的词首（忽略标点）
b       跳到当前单词或上一个单词的词首
B       同上，忽略标点
e       跳到当前单词或下一个单词的词尾
E       同上，忽略标点
ge      跳到上一个单词的词尾
gE      同上，忽略标点
```

Vim 把单词分成两种：「由字母数字下划线组成的单词」（`word`）和「由非空白字符组成的单词」（`WORD`）。`w` 和 `W` 的区别就在这里：

```
hello.world, how-are-you?
^   ^           ^
w   w           w       <- w 按标点和单词边界跳转
^         ^     ^
W         W     W       <- W 只按空白字符跳转
```

#### 行内移动

```vim
0       跳到行首（第一个字符）
^       跳到行首（第一个非空白字符）
$       跳到行尾
g_      跳到行尾（最后一个非空白字符）
f{char} 跳到行内下一个指定字符上
F{char} 跳到行内上一个指定字符上
t{char} 跳到行内下一个指定字符之前
T{char} 跳到行内上一个指定字符之后
;       重复上一次 f/F/t/T 搜索
,       反向重复上一次 f/F/t/T 搜索
```

`f` 命令非常实用。例如在一行中 `f(` 可以直接跳到左括号，`;` 跳到下一个。

#### 文件级移动

```vim
gg      跳到文件第一行
G       跳到文件最后一行
{number}G  跳到第 number 行（或者 `:{number} 回车`）
Ctrl-d  向下翻半页（down half）
Ctrl-u  向上翻半页（up half）
Ctrl-f  向下翻一页（forward full）
Ctrl-b  向上翻一页（backward full）
H       跳到屏幕顶部（High）
M       跳到屏幕中间（Middle）
L       跳到屏幕底部（Low）
zt      将光标所在行放到屏幕顶部
zz      将光标所在行放到屏幕中间
zb      将光标所在行放到屏幕底部
```

#### 代码结构移动

```vim
%       跳到匹配的括号（{ } [ ] ( )）
[[      跳到上一个函数/代码块开头
]]      跳到下一个函数/代码块开头
[]      跳到上一个函数/代码块结尾
][      跳到下一个函数/代码块结尾
```

### 2.2 插入：进入打字模式

**进入 Insert 方式的不同姿势对应不同场景：**

```vim
i       在光标前插入（insert）
I       在行首插入
a       在光标后插入（append）
A       在行尾插入
o       在当前行下方新建一行插入（open new line）
O       在当前行上方新建一行插入
s       删除光标下字符并进入插入（substitute）
S       删除整行并进入插入
cw      删除从光标到词尾并进入插入（change word）
cc      删除整行并进入插入
C       删除从光标到行尾并进入插入
```

**重要原则**：在你想要插入的地方，先移动到那里（用 Normal 模式的移动命令），然后选择最合适的进入插入方式。

### 2.3 删除

```vim
x       删除光标下的字符（像打字机的退格键）
X       删除光标前的字符
d{motion}   删除 motion 覆盖的文本（核心操作符）
dd      删除当前行
D       删除从光标到行尾（等同于 d$）
dw      删除到词尾
db      删除到词首
diw     删除光标所在的单词（包括空格不删）
daw     删除光标所在的单词（包括空格删）
d0      删除到行首
d$      删除到行尾
```

`d` 是操作符（operator），后面跟的是动作（motion）。这是 Vim 最核心的语法。

### 2.4 修改

```vim
r{char}     把光标下字符替换为 {char}（不用进 Insert 模式）
R           进入替换模式——键入的字符会覆盖现有字符
~           切换光标下字符的大小写
gu{motion}  将 motion 覆盖的文本转为小写
gU{motion}  将 motion 覆盖的文本转为大写
g~~         翻转整行大小写
```

### 2.5 撤销与恢复

```vim
u           撤销上一次操作（undo）
Ctrl-r      重做（redo 被撤销的操作）
.           重复上一次修改（点命令——威力巨大）
```

**点命令（`.`）是 Vim 效率的秘密武器。** 它重复的是「从进入 Insert 模式到退出 Insert 模式」之间发生的所有更改。如果你执行了 `ciw`（删除一个单词并进入插入），输入了新词然后按 `Esc`，按 `.` 就会重复这个完整的「替换单词」操作。这比手动剪切粘贴快得多。

### 2.6 操作符 + 动作：Vim 的核心语法

如果说其他编辑器是「菜单式操作」（点这里、选那里），Vim 的操作方式是 **语言式** 的——用操作符（动词）和动作（宾语）组合出丰富的含义。

```
d   +   w       =   dw       删除一个单词
d   +   $       =   d$       删到行尾
d   +   G       =   dG       删到文件末尾
c   +   i       +   w   =   ciw      修改一个单词（删掉并进入插入）
y   +   i       +   p   =   yip      复制当前段落
gU  +   i       +   w   =   guiw     将当前单词转为大写
```

**操作符列表：**

| 操作符 | 含义 |
|--------|------|
| `d` | 删除（delete） |
| `c` | 修改（change）= 删除 + 进入 Insert 模式 |
| `y` | 复制到寄存器（yank） |
| `gu` | 转小写 |
| `gU` | 转大写 |
| `g~` | 翻转大小写 |
| `>` | 向右缩进 |
| `<` | 向左缩进 |
| `=` | 自动缩进（格式化代码） |
| `!` | 用外部命令过滤 |

**动作（motion）列表：**

| 动作 | 含义 |
|------|------|
| `w` | 到下一个词首 |
| `b` | 到词首 |
| `e` | 到词尾 |
| `$` | 到行尾 |
| `0` | 到行首 |
| `G` | 到文件末尾 |
| `gg` | 到文件开头 |
| `%` | 到匹配括号 |
| `i{` | 在一对大括号内部 |
| `a{` | 在一对大括号（包括括号本身） |
| `it` | 在 XML/HTML 标签内部 |
| `at` | 在一个 XML/HTML 标签内 |

掌握这个语法后，你不再「执行命令」，而是 **用 Vim 说话**。看到一段代码需要改成大写，你不是想着「选中、右键、转大写」，而是 `gUiw`（大写当前单词）。

> **练习**：每天花 5 分钟玩 https://vimgenius.com/，建立肌肉记忆。

## 第三章：高级移动与编辑

### 3.1 文本对象（Text Objects）

文本对象是 Vim 最聪明的设计之一。它让 Vim 能理解「一个单词」「一对引号」「一个段落」这样的文本单元。

**语法：** `操作符 + i/a + 对象`

- `i` = inner（内部，不含包围字符）
- `a` = around（外部，包含包围字符）

```vim
iw      当前单词（inner word）
aw      当前单词（包括周围空白，around word）
iW      当前 WORD（inner WORD，word 和 WORD 的区别见前文）
aW      当前 WORD（包括空白）

ip      当前段落（inner paragraph）
ap      当前段落（包括空行）

i( 或 ib   一对圆括号内部（inner block）
a( 或 ab   一对圆括号（包括括号）

i{ 或 iB   一对花括号内部
a{ 或 aB   一对花括号（包括花括号）

i[      一对方括号内部
a[      一对方括号（包括方括号）

i<      一对尖括号内部
a<      一对尖括号（包括尖括号）

i'      一对单引号内部
a'      一对单引号（包括引号）
i"      一对双引号内部
a"      一对双引号（包括引号）
i`      一对反引号内部
a`      一对反引号（包括引号）

it      XML/HTML 标签内部（inner tag）
at      XML/HTML 标签（包括标签本身）
```

**实战例子：**

```
"hello world"     光标在 hello 中间时——
                   ci"   => 删除 hello world 并进入插入（清空引号内容）
                   da"   => 删除 "hello world"（包括引号）
                   ca"   => 删除 "hello world" 并进入插入

function foo() {   光标在 { 上时——
    return 1;       ci{   => 清空函数体进入插入
}                  da{   => 删除整个函数体包括 {} 
```

文本对象的最大价值：**你不需要精确选中**。光标只要在对象「内部」或「旁边」即可。Vim 自己负责找到对象的边界。

### 3.2 配合数字

数字放在命令前面表示「重复 N 次」：

```vim
3w      向右跳 3 个单词
5j      向下移动 5 行
2dd     删除 2 行
3yy     复制 3 行
d3w     删除 3 个单词
4x      删除 4 个字符
```

数字和操作符 + 动作的组合非常强大：

```vim
d2w     删除 2 个单词
c3j     修改下面 3 行（相当于 3cc 但更灵活）
y5k     复制上面 5 行
>3j     将下面 3 行向右缩进
```

### 3.3 寄存器概念

Vim 的寄存器就像多组剪贴板。默认的 `d`、`x`、`y` 都使用未命名的寄存器，但你可以精确控制。

**寄存器类型：**

| 寄存器 | 标识 | 说明 |
|--------|------|------|
| 未命名寄存器 | `""` | 默认使用，上一次删除或复制的内容 |
| 命名寄存器 | `"a` 到 `"z` | 手动指定，26 个独立存储位 |
| 系统剪贴板 | `"+` | 与操作系统的剪贴板互通 |
| 选择寄存器 | `"*` | X11 选择缓冲区（Linux） |
| 黑洞寄存器 | `"_` | 删除的内容不保存（真正丢弃） |
| 表达式寄存器 | `"=` | 用于计算数学表达式 |
| 小删除寄存器 | `"-` | 少于一行的小删除 |
| 文件名寄存器 | `"%` | 当前文件名 |
| 文件路径寄存器 | `"#` | 交替文件名 |

**用法：**

```vim
"ayiw        将当前单词复制到寄存器 a
"ap          粘贴寄存器 a 的内容
"bdd         删除当前行，存入寄存器 b
"+y          复制到系统剪贴板
"+p          从系统剪贴板粘贴
"_dw         删除单词但不存入任何寄存器（不污染默认剪贴板）
```

**在 Neovim 中**，系统剪贴板通常需要配置。确保你有剪贴板工具：

```bash
# 检查 Neovim 是否支持剪贴板
:checkhealth

# Linux 需要安装 xclip 或 xsel
sudo apt install xclip

# macOS 自带 pbcopy/pbpaste
# Windows 上 Neovim 通常开箱即用
```

或者在你的配置里加上：

```lua
vim.opt.clipboard = "unnamedplus"  -- 让 Neovim 的默认寄存器与系统剪贴板同步
```

### 3.4 复制与粘贴

```vim
y      复制选中内容（yank）
yy     复制当前行
Y      复制到行尾（与 yy 不同，Y = y$）
yw     复制一个单词
yiw    复制当前单词（不带空格）
y3j    复制当前行及下面 3 行（共 4 行）
p      在光标后粘贴（put）
P      在光标前粘贴
gp     粘贴并在粘贴内容后移动光标
gP     粘贴并在粘贴内容前移动光标
```

**粘贴来自不同寄存器的值：**

```vim
"ap     粘贴寄存器 a 的内容
"+p     从系统剪贴板粘贴
```

### 3.5 可视模式（Visual Mode）

可视模式让你先选中文本，再对选中内容执行操作。虽然不如操作符 + 动作「纯正」，但某些场景更直观。

```vim
v       进入字符可视模式（按字符选择）
V       进入行可视模式（按行选择）
Ctrl-v  进入块可视模式（矩形区域选择）
gv      重新选中上次的选择区域
```

**典型用例：**

- `Vjjj>` —— 选中 4 行，向右缩进
- `Ctrl-v` 选中多行某列，`I` `# ` `Esc` —— 在多行前加注释
- `Ctrl-v` 选中多行末尾，`A` `;` `Esc` —— 在多行末尾加分号
- `vip` 选中当前段落，`J` —— 合并段落为一行
- `vip` `d` —— 删除当前段落

**块模式特别强大**，用于处理表格或代码中的列操作：

```
选中列 -> I 输入 -> Esc    所有选中行同时插入
选中列 -> d                删除选中列
选中列 -> r 字符           替换选中列为单个字符
选中列 -> ~                翻转选中区域大小写
```

### 3.6 语法补全

Vim 内置的补全主要通过 **关键字补全**（从当前打开的文件和 tags 中识别单词）：

```vim
Ctrl-n  在 Insert 模式下，插入下一个匹配的单词
Ctrl-p  在 Insert 模式下，插入上一个匹配的单词
Ctrl-x Ctrl-f  文件名补全
Ctrl-x Ctrl-l  整行补全
Ctrl-x Ctrl-]  tags 补全
Ctrl-x Ctrl-o  全能补全（Omni-completion，需要语言特定支持）
Ctrl-x Ctrl-k  字典补全
```

**对于现代开发，你应该用 LSP 补全代替内置补全**（见第八章）。但在没有 LSP 的环境（服务器、配置文件编辑）里，`Ctrl-n`/`Ctrl-p` 依然是最快的补全方式。

## 第四章：查找与替换

### 4.1 行内搜索

行内搜索是 `f` 和 `t` 系列命令，用于在当前行内快速定位到特定字符。

```vim
f{char}       跳到下一个 char 所在位置
F{char}       跳到上一个 char 所在位置
t{char}       跳到下一个 char 的前一个字符
T{char}       跳到上一个 char 的后一个字符
;             重复上一次 f/F/t/T 搜索
,             反向重复上一次 f/F/t/T 搜索
```

**高效使用技巧：**

```
假设你在这一行：const greeting = "Hello, World!";
光标停在行首，你想跳到 "Hello" 的 H 上
f"  -> 跳到第一个引号
;   -> 跳到第二个引号（"Hello" 之前）

或者 fH -> 直接跳到 H（如果 H 是第一个匹配的 H）
```

**`f/t` 配合操作符的典型用法：**

```vim
dft    从光标删除到（但不包括）下一个 t
cf"    将光标到下一个引号之间的内容替换
yf;    将光标到下一个分号之间的内容复制
```

### 4.2 全局搜索

Vim 的全局搜索使用 `/` 和 `?`：

```vim
/pattern        正向搜索 pattern
?pattern        反向搜索 pattern
n               跳到下一个匹配
N               跳到上一个匹配
*               搜索光标下的单词（正向）
#               搜索光标下的单词（反向）
```

**搜索技巧：**

```
/\cpattern      不区分大小写搜索
/\Cpattern      区分大小写搜索（覆盖 ignorecase 设置）
/^pattern       只搜索行首
/pattern$       只搜索行尾
/pattern1\|pattern2  搜索 pattern1 或 pattern2
/pattern\ze     pattern 后面跟着其他文字但只搜索 pattern 本身
```

当搜索历史积累后，在 `/` 或 `?` 后按 `Ctrl-p`/`Ctrl-n` 可以浏览之前的搜索记录。

### 4.3 搜索高亮与设置

```vim
:set hlsearch       启用搜索高亮（匹配项会高亮显示）
:set nohlsearch     关闭搜索高亮
:set incsearch      启用增量搜索（边打边显示匹配）
:nohlsearch         临时取消当前的高亮（不会关闭功能，下一次搜索又会高亮）
```

**常用配置（放 .vimrc / init.lua）：**

```vim
" VimScript
set hlsearch
set incsearch
set ignorecase
set smartcase
" smartcase 的意思是：如果搜索词包含大写字母则区分大小写，否则不区分
```

```lua
-- Lua（Neovim）
vim.opt.hlsearch = true
vim.opt.incsearch = true
vim.opt.ignorecase = true
vim.opt.smartcase = true
```

**快速清除搜索高亮的技巧：**

```vim
" 映射 <Esc><Esc> 来清除高亮
nnoremap <Esc><Esc> :nohlsearch<CR>
```

```lua
-- Neovim Lua
vim.keymap.set("n", "<Esc><Esc>", ":nohlsearch<CR>")
```

### 4.4 替换命令 `:s` 完整用法

`:s`（substitute）是 Vim 最强大的命令之一。

**基础语法：**

```vim
:s/old/new         将当前行第一个 old 替换为 new
:s/old/new/g       将当前行所有 old 替换为 new（g = global）
:s/old/new/gc      替换前询问确认（c = confirm）
:s/old/new/gi      不区分大小写替换（i = ignore case）
```

**范围控制：**

```vim
:%s/old/new/g      在整个文件里替换（% 代表所有行）
:5,10s/old/new/g   在第 5 到 10 行之间替换
:.,$s/old/new/g    从当前行到文件末尾
:.,+5s/old/new/g   当前行及下面 5 行
:'<,'>s/old/new/g  在可视模式选中的区域里替换
```

**替换确认（`:s///gc`）：**

当你加上 `c` 标志，Vim 会对每个匹配询问：

| 按键 | 动作 |
|------|------|
| `y` | 执行本次替换 |
| `n` | 跳过本次匹配 |
| `a` | 替换所有剩余匹配 |
| `q` | 退出替换 |
| `l` | 替换本次并退出（last） |
| `^E` | 向上滚动 |
| `^Y` | 向下滚动 |

**高级替换模式：**

```vim
" 捕获分组与反向引用
:%s/\(foo\) \(bar\)/\2 \1/g    将 "foo bar" 替换为 "bar foo"

" 使用 \1 \2 \3 ... 引用分组 ( )( ) 中的内容
:%s/"\([^"]*\)"/'\1'/g         将双引号替换为单引号，保留内容

" 非数字捕获: %()
" Vim9+ 和 Neovim 支持 \%() 作为非捕获分组
:%s/\%(foo\) \(bar\)/\1/g      不捕获 foo，只捕获 bar

" 转义符在替换中的特殊含义
:%s/foo/\r/g                   将 foo 替换为换行符（\r = 换行）
:%s/foo/\\/g                   将 foo 替换为反斜杠
:%s/foo/\t/g                   将 foo 替换为制表符
```

**Neovim 的 `magic` 模式：**

Neovim 默认启用 `magic`（`:set magic`），但推荐使用 `very magic` 模式——在搜索模式前加 `\v`：

```vim
" 常规模式：需要转义括号和 |
/foo\|bar        匹配 foo 或 bar

" Very magic 模式：几乎所有字符都按特殊含义解释
/\v(foo|bar)    更自然的正则写法
```

### 4.5 快速修复列表（Quickfix）

快速修复是 Vim 的编译-错误列表系统，但它的用途远不止编译：

```vim
:vimgrep /pattern/ **/*.js    在整个项目中搜索 pattern
:vimgrep /pattern/ %           在当前文件中搜索
:vimgrep /pattern/ path/**/*.{js,ts}

:copen          打开快速修复窗口
:cclose         关闭快速修复窗口
:cnext          跳到下一个匹配
:cprev          跳到上一个匹配
:cfirst         跳到第一个匹配
:clast          跳到最后一个匹配
:cnfile         跳到下一个文件中的第一个匹配
:cpfile         跳到上一个文件中的最后一个匹配
```

`:vimgrep` 使用 Vim 内置的搜索引擎。对于大项目可能较慢，但好处是无需外部工具且跨平台。

### 4.6 集成 grep/ripgrep

对于大型项目，你应该用外部搜索工具代替 `:vimgrep`。

**结合 `grep`：**

```vim
:grep -rn "pattern" /path/to/search
:copen
```

**结合 `ripgrep`（`rg`）——这是推荐方案：**

```vim
" 在 .vimrc / init.lua 中设置
" VimScript
set grepprg=rg\ --vimgrep\ --no-heading\ --smart-case
set grepformat=%f:%l:%c:%m

" Neovim Lua
vim.opt.grepprg = "rg --vimgrep --no-heading --smart-case"
vim.opt.grepformat = "%f:%l:%c:%m"

" 使用
:grep "pattern"
:copen
```

ripgrep 比传统 `grep` 快 10-100 倍，自动忽略 `.gitignore` 中的文件，是 Vim/Neovim 的最佳搜索伴侣。

**更现代的方式：** 使用 Telescope.nvim（见第八章）进行实时模糊搜索，体验比 Quickfix 更流畅。

## 第五章：窗口、标签页与缓冲区

### 5.1 缓冲区概念

Vim 中打开的文件叫做 **缓冲区（buffer）**。缓冲区是文件在内存中的副本。

```vim
:ls                 列出所有已打开的缓冲区
:ls!                列出所有缓冲区（包括隐藏的）
:buffer N 或 :b N    跳转到编号为 N 的缓冲区
:bnext 或 :bn       下一个缓冲区
:bprevious 或 :bp   上一个缓冲区
:bfirst             第一个缓冲区
:blast              最后一个缓冲区
:bd                 关闭当前缓冲区（buffer delete）
:bw                 彻底清除当前缓冲区（buffer wipeout）
:bufdo {command}    在所有缓冲区上执行命令
```

**`:bufdo` 威力巨大：**

```vim
:bufdo %s/old/new/ge | update   在所有打开的文件中替换并保存
:bufdo set noet                  在所有缓冲区中修改缩进设置
```

`e` 标志表示「如果当前行不匹配就静默跳过」，`update` 表示「如果文件被修改过就保存」。

**缓冲区 vs 文件：**

- 打开文件 = 创建缓冲区
- 编辑不保存 = 缓冲区被修改但磁盘文件不变
- `:q` 关闭的是窗口，不是缓冲区

### 5.2 窗口分割

窗口（window）是缓冲区在屏幕上的显示区域。一个缓冲区可以在多个窗口中显示。

```vim
:split 或 :sp {file}        水平分割窗口
:vsplit 或 :vs {file}       垂直分割窗口
:new                        水平分割并创建新文件
:vnew                       垂直分割并创建新文件

" 窗口导航
Ctrl-w h/j/k/l             在不同窗口间移动
Ctrl-w w                    循环切换到下一个窗口
Ctrl-w H/J/K/L              将当前窗口移动到最左/下/上/右

" 窗口大小调整
Ctrl-w =                    让所有窗口等宽等高
Ctrl-w +                    增加当前窗口高度
Ctrl-w -                    减少当前窗口高度
Ctrl-w >                    增加当前窗口宽度
Ctrl-w <                    减少当前窗口宽度
:resize 20                  设置当前窗口高度为 20 行
:vertical resize 80         设置当前窗口宽度为 80 列

" 关闭窗口
Ctrl-w c                    关闭当前窗口（close）
Ctrl-w o                    只保留当前窗口，关闭其他（only）
:q                          关闭当前窗口（如果只剩一个窗口则退出 Vim）
```

### 5.3 标签页

标签页（tab page）是窗口的集合。一个标签页可以包含多个窗口。

```vim
:tabnew {file}              在新标签页中打开文件
:tabe {file}                同上
:tabnext 或 gt              下一个标签页
:tabprevious 或 gT          上一个标签页
:tabfirst                   第一个标签页
:tablast                    最后一个标签页
:tabclose                   关闭当前标签页
:tabonly                    关闭其他标签页
:-tabmove                   向左移动标签页
:+tabmove                   向右移动标签页
:0tabmove                   将标签页移到最左
```

**注意：** Vim 的标签页**不是**像浏览器那样「多个文件各占一个标签」。Vim 的标签页是 **布局容器**。你应该按工作空间或任务来组织标签页。

**一个典型工作流：**

```
标签页 1：主代码 + 右侧测试文件（水平分屏）
标签页 2：配置文件（单窗口）
标签页 3：终端（:term）
标签页 4：Git 操作（fugitive 的 git 状态窗口）
```

### 5.4 缓冲区的隐藏（hidden）

默认情况下，如果缓冲区未保存，`:q` 或切换缓冲区时会报错。设置 `hidden` 允许在未保存时切换缓冲区：

```vim
set hidden
```

```lua
vim.opt.hidden = true
```

设置后你可以随意在缓冲区间切换，Vim 会记住未保存的修改。当你真的想关闭 Vim 时再用 `:qa!` 或逐个确认。

### 5.5 实际工作流演示

**场景：调试一个 bug**

1. `:e src/buggy.js` —— 打开有 bug 的文件
2. `/theBug` —— 搜索可能出问题的地方
3. `:vsp src/test.js` —— 垂直分割打开测试文件
4. `Ctrl-w w` —— 切换到另一个窗口
5. 反复切换、编辑、测试
6. `:bn` —— 切到配置缓冲区微调配置
7. `:bd buggy.js` —— 工作完成，关闭该缓冲区
8. `:q` —— 退出

**场景：项目重构**

1. `nvim src/main.js` —— 打开入口文件
2. `gt` 新建标签页
3. `:telescope find_files` —— 模糊搜索文件
4. 选中文件开始修改
5. `Ctrl-w v` 分割窗口查看两个相关文件
6. `:vimgrep /oldFunction/ **/*.js` —— 搜索所有引用
7. `:copen` 查看结果，用 `:cnext`/`:cprev` 遍历
8. 逐个替换

## 第六章：配置入门

### 6.1 .vimrc 基础结构

Vim 的配置文件位于 `~/.vimrc`（Vim）或 `~/.config/nvim/init.lua`（Neovim）。

**一个最小可用的 Vim 配置：**

```vim
" ~/.vimrc

" 基础设置
set nocompatible            " 不兼容 vi 模式
set encoding=utf-8          " 编码
set number                  " 显示行号
set relativenumber          " 显示相对行号（与 number 配合使用）
set cursorline              " 高亮当前行
set tabstop=4               " Tab 显示宽度
set shiftwidth=4            " 缩进宽度
set expandtab               " 用空格代替 Tab
set autoindent              " 自动缩进
set smartindent             " 智能缩进

" 搜索设置
set hlsearch                " 高亮搜索匹配
set incsearch               " 增量搜索
set ignorecase              " 搜索不区分大小写
set smartcase               " 智能大小写（如果搜索有大写则区分）

" 编辑体验
set hidden                  " 允许未保存时切换缓冲区
set scrolloff=5             " 滚动时保留上下 5 行上下文
set wildmenu                " 命令补全菜单
set wildmode=list:longest   " 命令补全模式
set mouse=a                 " 启用鼠标支持
set clipboard=unnamedplus   " 与系统剪贴板同步

" 行号模式切换（Normal 模式显示绝对行号，Insert 模式显示相对行号）
autocmd InsertEnter * :set norelativenumber
autocmd InsertLeave * :set relativenumber

" 快捷键
nnoremap <leader>w :w<CR>           " <Space>w 保存文件
nnoremap <leader>q :q<CR>           " <Space>q 退出
nnoremap <leader>e :q!<CR>          " <Space>e 强制退出
" <leader> 默认是反斜杠，但很多人映射为空格
let mapleader = " "
```

### 6.2 Neovim 的 Lua 配置 vs VimScript

Neovim 支持用 Lua 配置，这比 VimScript 更现代、更易读、性能更好。

**VimScript 写法：**
```vim
set number
set tabstop=4
" 映射
nnoremap <leader>w :w<CR>
" autocmd
autocmd BufWritePre *.js :%s/\s\+$//e
```

**对应的 Lua 写法：**
```lua
-- ~/.config/nvim/init.lua

vim.opt.number = true
vim.opt.tabstop = 4

-- 映射
vim.keymap.set("n", "<leader>w", ":w<CR>")

-- autocmd
vim.api.nvim_create_autocmd("BufWritePre", {
    pattern = "*.js",
    command = [[%s/\s\+$//e]],
})
```

**两种写法的对应关系：**

| VimScript | Lua | 说明 |
|-----------|-----|------|
| `set number` | `vim.opt.number = true` | 布尔选项 |
| `set tabstop=4` | `vim.opt.tabstop = 4` | 数值选项 |
| `set wildmode=list:longest` | `vim.opt.wildmode = "list:longest"` | 字符串选项 |
| `set expandtab` | `vim.opt.expandtab = true` | 布尔选项的另一种 |
| `set noexpandtab` | `vim.opt.expandtab = false` | 禁用布尔选项 |
| `set hlsearch!` | `vim.opt.hlsearch = not vim.opt.hlsearch:get()` | 切换 |
| `nnoremap <c-s> :w<CR>` | `vim.keymap.set("n", "<c-s>", ":w<CR>")` | 键映射 |
| `inoremap jk <Esc>` | `vim.keymap.set("i", "jk", "<Esc>")` | Insert 模式 |
| `vnoremap > >gv` | `vim.keymap.set("v", ">", ">gv")` | Visual 模式 |
| `autocmd BufWritePre *.js %s/\s\+$//e` | `vim.api.nvim_create_autocmd("BufWritePre", { pattern = "*.js", command = [[%s/\s\+$//e]] })` | autocmd |
| `let mapleader = " "` | `vim.g.mapleader = " "` | 全局变量 |
| `set runtimepath+=/path` | `vim.opt.runtimepath:append("/path")` | 列表操作 |

### 6.3 从 .vimrc 迁移到 init.lua

不要一次性迁移。循序渐进：

1. 先从最简单的选项开始，用 `vim.opt` 替换 `set`
2. 把键映射换成 `vim.keymap.set`
3. 把 autocmd 换成 `vim.api.nvim_create_autocmd`
4. 最后使用 `require()` 加载插件配置

```lua
-- ~/.config/nvim/init.lua （完整基配置示例）

-- 选项
vim.opt.nocompatible = true
vim.opt.encoding = "utf-8"
vim.opt.number = true
vim.opt.relativenumber = true
vim.opt.tabstop = 4
vim.opt.shiftwidth = 4
vim.opt.expandtab = true
vim.opt.hlsearch = true
vim.opt.incsearch = true
vim.opt.ignorecase = true
vim.opt.smartcase = true
vim.opt.hidden = true
vim.opt.scrolloff = 8
vim.opt.mouse = "a"
vim.opt.clipboard = "unnamedplus"
vim.opt.splitright = true
vim.opt.splitbelow = true

-- leader 键
vim.g.mapleader = " "

-- 通用映射
local map = vim.keymap.set
local opts = { noremap = true, silent = true }

map("n", "<leader>w", ":w<CR>", opts)
map("n", "<leader>q", ":q<CR>", opts)
map("n", "<leader>Q", ":q!<CR>", opts)
map("n", "<leader>e", ":e $MYVIMRC<CR>", opts)
map("n", "<Esc><Esc>", ":nohlsearch<CR>", opts)
map("i", "jk", "<Esc>", opts)        -- jk 代替 Esc（不用伸手到键盘左上角）
map("n", "J", "5j", opts)            -- J 代替 5j
map("n", "K", "5k", opts)            -- K 代替 5k

-- autocmd
vim.api.nvim_create_autocmd("InsertEnter", {
    command = "set norelativenumber"
})
vim.api.nvim_create_autocmd("InsertLeave", {
    command = "set relativenumber"
})
vim.api.nvim_create_autocmd("TextYankPost", {
    callback = function()
        vim.highlight.on_yank { timeout = 200 }
    end
})
```

### 6.4 插件管理器

**Vim 推荐：vim-plug**

```vim
" ~/.vimrc
call plug#begin('~/.vim/plugged')

Plug 'preservim/nerdtree'          " 文件浏览器
Plug 'tpope/vim-fugitive'          " Git 集成
Plug 'vim-airline/vim-airline'     " 状态栏美化
Plug 'raimondi/delimitmate'        " 自动补全括号

call plug#end()
```

安装：`:PlugInstall`

**Neovim 推荐：lazy.nvim**

lazy.nvim 是目前 Neovim 生态最好的插件管理器。它支持按需加载、自动更新、配置独立管理。

```lua
-- ~/.config/nvim/init.lua（用 lazy.nvim 管理）

-- 安装 lazy.nvim（如果没有）
local lazypath = vim.fn.stdpath("data") .. "/lazy/lazy.nvim"
if not vim.loop.fs_stat(lazypath) then
    vim.fn.system({
        "git",
        "clone",
        "--filter=blob:none",
        "https://github.com/folke/lazy.nvim.git",
        "--branch=stable",
        lazypath,
    })
end
vim.opt.rtp:prepend(lazypath)

-- 加载插件
require("lazy").setup({
    -- 主题
    { "sainnhe/everforest" },

    -- 文件浏览器
    {
        "nvim-tree/nvim-tree.lua",
        dependencies = { "nvim-tree/nvim-web-devicons" },
        config = function()
            require("nvim-tree").setup()
        end,
    },

    -- 模糊搜索
    {
        "nvim-telescope/telescope.nvim",
        dependencies = {
            "nvim-lua/plenary.nvim",
            "BurntSushi/ripgrep",
        },
        config = function()
            require("telescope").setup()
        end,
    },

    -- LSP 相关
    {
        "neovim/nvim-lspconfig",
        config = function()
            require("lsp-config")
        end,
    },

    -- Treesitter
    {
        "nvim-treesitter/nvim-treesitter",
        build = ":TSUpdate",
        config = function()
            require("nvim-treesitter.configs").setup({
                ensure_installed = { "lua", "javascript", "typescript", "rust", "python" },
                highlight = { enable = true },
            })
        end,
    },
})

-- 设置主题
vim.cmd.colorscheme("everforest")
```

lazy.nvim 的特点是把每个插件的配置写在一个 `{}` 内，自包含、可维护。如果你有复杂的配置，可以拆分成独立文件放在 `~/.config/nvim/lua/plugins/` 下。

## 第七章：宏（Macros）

### 7.1 什么是宏

宏是你录制的一系列操作，可以回放任意次数。它是 Vim 中处理**重复性任务**的最强工具。

如果说「操作符 + 动作」是 Vim 的语言，宏就是把一段对话录下来反复播放。

### 7.2 录制与回放

**基本流程：**

```vim
qa          开始录制宏到寄存器 a
... 执行一系列操作 ...
q           停止录制
@a          回放寄存器 a 中的宏
@@          重复上一次的宏回放
```

**寄存器选择：** 可以用 `a`-`z`（26 个寄存器），建议用 `q` 作为临时录制寄存器。

**录制时的注意事项：**

1. 录制前确保光标位置正确
2. 操作应该**可重复**——用 `w`、`f` 等相对移动，不要用 `j` 硬编码行数
3. 录制结束时一定有 `q`，别忘了
4. 如果录错了，重新录（覆盖同一个寄存器）

### 7.3 典型示例

**场景：给每一行加前缀**

原始数据：
```
apple
banana
cherry
date
```

目标：每行前面加 `- ` 变成 Markdown 列表。

录制步骤：
```
1. 光标在第一行
2. qa       开始录制到寄存器 a
3. I- <Esc>  在行首插入 "- " 
4. j        下一行
5. q        停止录制
6. @a       回放一次，看效果
7. 3@a      回放 3 次，完成所有行
```

**场景：批量修改变量名**

原始数据：
```
let old_name = "Alice"
let old_name = "Bob"
let old_name = "Charlie"
```

把每行的 `old_name` 改为 `new_name`：

```
1. 光标在第一行的 old 上
2. qa
3. ciw    删除 old 并进入插入（c + i + w = change inner word）
4. new    输入 new
5. <Esc>  退出插入
6. j      下一行（回到行首，准备下一次）
7. q
8. 2@a    回放两次
```

**关键技巧：** 在宏的最后一步，**让光标停在下一次操作开始的位置**。这是宏可重复的关键。

### 7.4 在多个文件上执行宏

宏可以结合 `:bufdo`、`:argdo`、`:windo` 在多文件上执行。

```vim
" 在 archivelist 中列出要操作的文件
:args src/*.js

" 在所有文件中执行宏 a
:argdo normal @a

" 或使用 bufdo：所有已打开的缓冲区
:bufdo normal @a

" 替换所有文件并保存
:argdo normal @a | update
```

### 7.5 编辑宏

录制好的宏存为文本，可以修改后再放回去。

```vim
:let @a = '你的宏内容'      直接修改寄存器的内容
"ap                          查看寄存器 a 的内容（在 Insert 模式下粘贴）
```

更常用的方法：

1. `"ap` 在文件中将宏粘贴为文本
2. 编辑文本
3. 选中编辑后的文本
4. `"ay` 重新复制回寄存器 a

**将宏保存到 .vimrc 中供以后使用：**

```vim
" 在 .vimrc 中
let @a = 'I-[Esc]j'
" 下次启动后 @a 仍然可用
```

### 7.6 递归宏

宏可以调用自身——在录制过程中调用 `@a`，实现递归或循环。

```vim
" 设置初始状态
qa             开始录制到 a
... 操作 ...
@a             在录制中调用自身（递归）
q              停止录制（需要按两次）

" 然后
@a             开始执行，会一直运行直到出现错误
```

递归宏必须有一个**终止条件**——通常是某个操作失败（比如 `j` 到文件末尾不能再往下翻了）。

**示例：递归执行直到文件末尾**

```vim
qa
j             下移一行
:.,+1s/foo/bar/g  替换两行的 foo
@a
q
```

当 `j` 到文件末尾时，不能再移动，宏自动终止。

### 7.7 宏的局限性

宏不是万能的。当你的逻辑需要条件判断（if/else）、计算、或者基于文本内容做不同操作时，宏就不太合适了。这时你应该：

- 用 **替换命令 `:s`**（第四章）做基于模式的替换
- 用 **`:g` 命令** 在匹配行上执行操作
- 用 **Python/Lua 脚本** 做复杂处理

`:g` 命令示例：

```vim
:g/pattern/normal @a   所有包含 pattern 的行上执行宏 a
:g/^$/d                 删除所有空行
:g/^#/t$                将所有注释行复制到文件末尾
```

## 第八章：Neovim 特色功能（重点）

Neovim 不只是 Vim 的「新版本」。它在架构上做了根本性的改进——**异步任务支持**、**内置 LSP 客户端**、**Tree-sitter 集成**、**Lua 作为一等公民**——让 Neovim 从一个编辑器变成了一个可编程的编辑平台。

### 8.1 内置 LSP（语言服务协议）

LSP 是一个标准协议，让编辑器与语言服务器通信。语言服务器知道你的代码结构，能提供：

- 自动补全
- 跳转到定义
- 查找引用
- 悬停显示文档
- 错误诊断
- 代码重构
- 重命名符号

**Neovim 内置了 LSP 客户端**，你不需要像 VS Code 那样装额外的插件来实现 LSP。你只需要配置：

**第一步：安装 lspconfig**

```lua
-- 用 lazy.nvim
{
    "neovim/nvim-lspconfig",
    config = function()
        require("lsp-config")
    end,
}

-- 也可以直接安装
-- :LazyInstall nvim-lspconfig
```

**第二步：安装语言服务器**

```lua
-- 方式一：手动安装（以 TypeScript 为例）
-- npm install -g typescript typescript-language-server

-- 方式二：使用 Mason（推荐，见下文）

-- 方式三：使用系统包管理器
-- sudo apt install clangd  （C/C++）
-- brew install lua-language-server  （Lua）
```

**第三步：配置 lspconfig**

```lua
-- ~/.config/nvim/lua/lsp-config.lua
local lspconfig = require("lspconfig")

-- 每个语言服务器需要独立的 setup 调用
lspconfig.ts_ls.setup({
    on_attach = function(client, bufnr)
        -- 当 LSP 附加到缓冲区时的配置
        local bufmap = function(mode, lhs, rhs, opts)
            opts = opts or { buffer = bufnr, noremap = true, silent = true }
            vim.keymap.set(mode, lhs, rhs, opts)
        end

        -- LSP 快捷键
        bufmap("n", "gd", vim.lsp.buf.definition)         -- 跳转到定义
        bufmap("n", "gr", vim.lsp.buf.references)         -- 查找引用
        bufmap("n", "K", vim.lsp.buf.hover)                -- 悬停文档
        bufmap("n", "<leader>rn", vim.lsp.buf.rename)      -- 重命名
        bufmap("n", "<leader>ca", vim.lsp.buf.code_action) -- 代码动作
        bufmap("n", "[d", vim.diagnostic.goto_prev)         -- 上一个诊断
        bufmap("n", "]d", vim.diagnostic.goto_next)         -- 下一个诊断
        bufmap("n", "<leader>e", vim.diagnostic.open_float)  -- 查看诊断详情
    end,
    capabilities = require("cmp_nvim_lsp").default_capabilities(),
})

lspconfig.lua_ls.setup({
    on_attach = ...,
    settings = {
        Lua = {
            runtime = { version = "LuaJIT" },
            diagnostics = { globals = { "vim" } },
            workspace = { library = vim.api.nvim_get_runtime_file("", true) },
        },
    },
})

lspconfig.rust_analyzer.setup({
    on_attach = ...,
})

lspconfig.pyright.setup({
    on_attach = ...,
})
```

**第四步：配置补全**

LSP 提供补全数据，但你需要一个补全引擎来展示：

```lua
-- 使用 nvim-cmp（最流行的 Neovim 补全插件）
{
    "hrsh7th/nvim-cmp",
    dependencies = {
        "hrsh7th/cmp-nvim-lsp",  -- LSP 源
        "hrsh7th/cmp-buffer",    -- 缓冲区词源
        "hrsh7th/cmp-path",      -- 路径补全
        "hrsh7th/cmp-cmdline",   -- 命令行补全
        "L3MON4D3/LuaSnip",      -- 代码片段
    },
    config = function()
        local cmp = require("cmp")
        cmp.setup({
            snippet = {
                expand = function(args)
                    require("luasnip").lsp_expand(args.body)
                end,
            },
            mapping = cmp.mapping.preset.insert({
                ["<C-b>"] = cmp.mapping.scroll_docs(-4),
                ["<C-f>"] = cmp.mapping.scroll_docs(4),
                ["<C-Space>"] = cmp.mapping.complete(),
                ["<C-e>"] = cmp.mapping.abort(),
                ["<CR>"] = cmp.mapping.confirm({ select = true }),
            }),
            sources = {
                { name = "nvim_lsp" },
                { name = "buffer" },
                { name = "path" },
            },
        })
    end,
}
```

### 8.2 Tree-sitter

Tree-sitter 是一个解析器生成工具和增量解析库。Neovim 用它替代传统的正则表达式语法高亮。

**Tree-sitter 提供：**

1. **更准确的语法高亮** —— 基于语法树，不是正则扫描
2. **增量解析** —— 编辑时只重新解析改变的部分，非常快
3. **语法感知的函数移动** —— `]]` `[[` 能正确跳转到函数边界
4. **文本对象扩展** —— 支持 `@function.outer/inner`、`@class.outer/inner` 等
5. **增量选择** —— `:h treesitter-textobjects`

**安装和基本配置：**

```lua
{
    "nvim-treesitter/nvim-treesitter",
    version = false,  -- 使用最新版
    build = ":TSUpdate",
    config = function()
        require("nvim-treesitter.configs").setup({
            -- 自动安装这些语言的 parser
            ensure_installed = {
                "lua",
                "vim",
                "vimdoc",
                "javascript",
                "typescript",
                "tsx",
                "html",
                "css",
                "json",
                "yaml",
                "markdown",
                "python",
                "rust",
                "c",
                "cpp",
                "go",
            },
            auto_install = true,  -- 打开新语言的文件时自动安装 parser

            highlight = {
                enable = true,     -- 启用语法高亮
                additional_vim_regex_highlighting = false,
            },
        })
    end,
}
```

**Tree-sitter 文本对象（需要 nvim-treesitter-textobjects 插件）：**

```lua
{
    "nvim-treesitter/nvim-treesitter-textobjects",
    config = function()
        require("nvim-treesitter.configs").setup({
            textobjects = {
                select = {
                    enable = true,
                    lookahead = true,
                    keymaps = {
                        ["af"] = "@function.outer",       -- 选择整个函数
                        ["if"] = "@function.inner",       -- 选择函数体内部
                        ["ac"] = "@class.outer",          -- 选择整个类
                        ["ic"] = "@class.inner",          -- 选择类体内部
                        ["ab"] = "@block.outer",          -- 选择整个代码块
                        ["ib"] = "@block.inner",          -- 选择代码块内部
                    },
                },
            },
        })
    end,
}
```

之后你可以用 `vif` 选中函数体内部，`daf` 删除整个函数——这些是传统 Vim 做不到的。

### 8.3 内置终端

Neovim 内置了一个终端模拟器，可以在编辑器里直接运行 shell：

```vim
:terminal      打开终端（水平分割）
:term          同上

:term node        运行 node REPL
:term npm test    运行 npm test
:term bash        打开 bash shell
```

**终端模式下的交互：**

```vim
" 在终端窗口中
i              进入终端模式（可以键入）
<Esc>          退出终端模式，回到 Normal 模式（可以移动和复制）

" 快捷键
Ctrl-\ Ctrl-n  从终端模式直接回到 Normal 模式
```

**终端窗口的典型用途：**

1. `:term npm run dev` —— 后台运行开发服务器
2. `:term` 然后在终端里 `git log --oneline` —— 不离开编辑器的 Git 操作
3. 分割终端窗口实时查看测试输出
4. 在终端中运行 REPL（Python、Node.js）

```lua
-- 方便的终端快捷键映射
vim.keymap.set("n", "<leader>t", ":terminal<CR>")
vim.keymap.set("t", "<Esc>", "<C-\\><C-n>")  -- Esc 从终端模式回到 Normal
```

### 8.4 Telescope.nvim 模糊搜索

Telescope 是 Neovim 的模糊查找器，比传统的文件搜索和 Grep 高效得多。

```lua
{
    "nvim-telescope/telescope.nvim",
    dependencies = {
        "nvim-lua/plenary.nvim",
        "nvim-treesitter/nvim-treesitter",
    },
    config = function()
        local builtin = require("telescope.builtin")
        vim.keymap.set("n", "<leader>ff", builtin.find_files)       -- 按文件名搜索
        vim.keymap.set("n", "<leader>fg", builtin.live_grep)        -- 按内容搜索
        vim.keymap.set("n", "<leader>fb", builtin.buffers)          -- 搜索缓冲区
        vim.keymap.set("n", "<leader>fh", builtin.help_tags)        -- 搜索 Vim help
        vim.keymap.set("n", "<leader>fr", builtin.oldfiles)         -- 最近文件
        vim.keymap.set("n", "<leader>fs", builtin.lsp_document_symbols)  -- 搜索文档符号
        vim.keymap.set("n", "<leader>fS", builtin.lsp_workspace_symbols) -- 搜索工作区符号
        vim.keymap.set("n", "gr", builtin.lsp_references)           -- 查找引用（用 Telescope 展示）
        vim.keymap.set("n", "gd", builtin.lsp_definitions)          -- 跳转定义
    end,
}
```

**核心功能：**

| 命令 | 功能 |
|------|------|
| `<leader>ff` | 按文件名搜索（fzf 风格模糊匹配） |
| `<leader>fg` | 实时搜索文件内容（依赖 ripgrep） |
| `<leader>fb` | 切换已打开的缓冲区 |
| `<leader>fh` | 搜索 Vim 帮助文档 |
| `<leader>fr` | 打开最近编辑的文件 |
| `<leader>fs` | 搜索当前文件中的符号（函数、类、变量） |
| `<leader>fS` | 搜索整个项目中的符号 |
| `gr` | 用 Telescope 展示所有引用 |
| `gd` | 用 Telescope 展示所有定义位置 |

**Telescope 是 Neovim 相对于 Vim 的一大优势。** 传统 Vim 用户需要 CtrlP 或 fzf.vim 来实现类似功能，但体验上 Telescope 更胜一筹。

**扩展 Telescope：**

```lua
-- 安装更多扩展
{
    "nvim-telescope/telescope-file-browser.nvim",
    config = function()
        require("telescope").load_extension("file_browser")
    end,
}

-- 使用
: Telescope file_browser
```

```lua
                bufmap("n", "gi", vim.lsp.buf.implementation)
                bufmap("n", "gr", vim.lsp.buf.references)
                bufmap("n", "<leader>rn", vim.lsp.buf.rename)
                bufmap("n", "<leader>ca", vim.lsp.buf.code_action)
            end

            local servers = { "lua_ls", "ts_ls", "rust_analyzer", "pyright" }
            for _, server in ipairs(servers) do
                lspconfig[server].setup({
                    on_attach = on_attach,
                    capabilities = capabilities,
                })
            end

            -- Lua 的特殊配置
            lspconfig.lua_ls.setup({
                on_attach = on_attach,
                capabilities = capabilities,
                settings = {
                    Lua = {
                        runtime = { version = "LuaJIT" },
                        diagnostics = { globals = { "vim" } },
                        workspace = {
                            library = vim.api.nvim_get_runtime_file("", true),
                        },
                    },
                },
            })
        end,
    },

    -- ── Treesitter ──
    {
        "nvim-treesitter/nvim-treesitter",
        build = ":TSUpdate",
        config = function()
            require("nvim-treesitter.configs").setup({
                ensure_installed = {
                    "lua", "vim", "vimdoc",
                    "javascript", "typescript", "tsx",
                    "html", "css", "json", "yaml",
                    "python", "rust", "go",
                },
                auto_install = true,
                highlight = { enable = true },
                indent = { enable = true },
            })
        end,
    },

    -- ── Git 集成 ──
    {
        "tpope/vim-fugitive",
        config = function()
            map("n", "<leader>gs", ":Git<CR>")
            map("n", "<leader>gc", ":Git commit<CR>")
            map("n", "<leader>gp", ":Git push<CR>")
            map("n", "<leader>gl", ":Git log<CR>")
        end,
    },

    -- ── 状态栏 ──
    {
        "nvim-lualine/lualine.nvim",
        dependencies = { "nvim-tree/nvim-web-devicons" },
        config = function()
            require("lualine").setup({
                options = { theme = "auto" },
            })
        end,
    },
})

-- ── 主题 ──
vim.cmd.colorscheme("everforest")
```

这个配置包含了现代编辑器所需的一切功能：文件浏览、模糊搜索、自动补全、LSP、语法高亮、Git 集成、美化状态栏。保存后启动 Neovim，运行 `:Lazy` 检查插件安装状态，然后 `:Mason` 安装你需要的 LSP 服务器。

## 第九章：真实工作流

### 9.1 日常编辑流程

**使用 Vim/Neovim 的典型一天：**

```bash
# 早上：打开项目
nvim .              # Neovim 启动在项目目录

# 用 Telescope 找到要改的文件
<leader>ff       -> 搜索文件名
回车打开

# 开始编辑
/functionName    -> 搜索特定函数
ciw              -> 修改单词
Ctrl-n           -> 补全
dd               -> 删除行
p                -> 粘贴
vip              -> 选中段落
J                -> 合并行
.                -> 重复上次操作

# 用 LSP 跳转
gd               -> 跳转到定义
Ctrl-o           -> 跳回
K                -> 查看悬停文档
gr               -> 查看引用

# 多文件修改
:vimgrep /pattern/ **/*.js   -> 搜索所有文件
:copen                         -> 打开结果
:cnext/:cprev                  -> 逐个跳转
```

**这个流程的核心：手不离开键盘主区域。** 从打开文件到完成修改，不需要鼠标，不需要方向键。

### 9.2 Git 集成

**vim-fugitive（Vim 和 Neovim 都可用）：**

```vim
:Git             打开 Git 状态窗口（类似 git status）
:Git add %       git add 当前文件
:Git commit      git commit（打开提交信息编辑窗口）
:Git push        git push
:Git pull        git pull
:Git log         查看提交历史
:Git blame       查看每一行的最近提交

:Gdiffsplit      对当前文件显示 diff 窗口
    " 在 diff 窗口中：
    ]c        跳到下一个 diff 块
    [c        跳到上一个 diff 块
    :diffput  将当前修改应用到对方
    :diffget  从对方获取修改
```

**典型 Git 工作流：**

```vim
" 1. 修改代码
" 2. 查看修改
:Git

" 3. 在缓冲区间导航
Ctrl-w w        切换到 Git 状态窗口
" 在 git 状态窗口中，光标放在文件上
-               暂存/取消暂存文件
cc              提交
dv              查看文件 diff

" 4. 提交
" 在提交信息缓冲区中编写信息
:wq             保存提交信息并提交

" 5. 推送
:Git push
```

### 9.3 文件浏览

**nvim-tree（推荐 Neovim 用户使用）：**

```lua
-- 在配置中

```

使用：

```
r                重命名
d                删除

```

**netrw（Vim 内置，不需要任何插件）：**

```vim

:Ex              打开文件浏览器

" 在 netrw 窗口中

```

### 9.4 多文件重构

**场景：将函数从 `file_a.js` 移动到 `file_b.js`**

```vim
" 1. 打开两个文件
:sp src/file_a.js       " 水平分割
:vsp src/file_b.js      " 再垂直分割

" 2. 在 file_a 中定位函数
/function_to_move

" 3. 剪切函数
V                     " 行可视模式选中
5j                    " 选中函数
d                     " 剪切

" 4. 切换到 file_b
Ctrl-w w              " 切换到右边窗口
/需要插入的位置
p                     " 粘贴

" 5. 更新引用
:args src/**/*.js     " 设置文件列表
:argdo %s/old_path\/lib\/file_a/new_path\/lib\/file_b/ge | update
" 在所有项目 JS 文件中替换路径
```

**更好的方式——使用 LSP 重命名：**

如果语言服务器支持，`<leader>rn` 是重构的首选方式。它会智能地找到所有引用并重命名。

## 第十章：学习路径与资源推荐

### 10.1 初学者到熟练的路径

**阶段一：适应（第 1-3 天）**

目标：克服对模态编辑的初反感，能用 Vim 做基本编辑。

- 完成 `vimtutor`（1-2 遍）
- 记住 `hjkl` 移动，尝试在日常编辑中使用它们
- 学会 `i`、`:wq`、`:q!` 基本生存命令
- 遇到困难时知道怎么退出（`Esc` + `:q!`）

**阶段二：建立习惯（第 1-2 周）**

目标：形成肌肉记忆，不再刻意去想按键。

- 在 IDE 里安装 Vim 插件（VS Code 的 Vim 插件、JetBrains 的 IdeaVim）
- 重点练习：`w`/`b`/`e`、`f`/`t`、`d`/`y`/`c` + 动作
- 练习 `.` 点命令的重复能力
- 每天用 https://vimgenius.com/ 练习 5 分钟
- 在 ~/Documents 里有 `notes.md` 当记事本，强制自己用 Vim 记笔记

**阶段三：提速（第 2-4 周）**

目标：编辑速度超过原来的编辑器。

- 练习数字修饰符（`d3w`、`y5j`、`>4k`）
- 熟练掌握文本对象（`ciw`、`da"`、`ca(`）
- 学会宏的录制和回放
- 开始使用 Vim 替换命令做批量修改
- 学会基本的 `.vimrc` 配置
- 引入 `:vimgrep` 或 Telescope 做项目搜索

**阶段四：深入（第 1-3 个月）**

目标：Vim 成为你的「母语编辑器」。

- 学习寄存器系统和精确的复制粘贴控制
- 掌握 `:g`、`:s` 和 `:bufdo` 等批量操作命令
- 编写自己的 VimScript 或 Lua 配置
- 使用 LSP 做代码补全、跳转、重构
- 学习 Vim 的折叠、标记、跳转列表
- 阅读 `:help` 文档——Vim 的帮助系统是最好的学习资源

**阶段五：精通（第 3-12 个月）**

目标：Vim 成为你的第二个大脑。

- 能编写复杂的 Lua/VimScript 脚本来扩展编辑功能
- 为不同的语言编写自定义 Treesitter 查询
- 能识别和优化 Vim/Neovim 的性能瓶颈
- 在服务器环境中纯终端工作流（无插件也高效）
- 开发自己的插件或为开源插件做贡献

### 10.3 如何逐步提升

**第一个月不要做的事情：**

- 不要追求「最快的配置」——用默认配置或最小配置
- 不要装超过 10 个插件——先学会用好默认功能
- 不要深入研究 VimScript——先把基本操作练熟
- 不要频繁切换配置——这会打断肌肉记忆的形成
- 不要追求「完全不用鼠标」——初期用鼠标是完全可以接受的

**循序渐进的原则：**

1. **先学会走路再跑步** —— `vimtutor` 是你唯一的必修课
2. **每次学一个新操作，用一周** —— 不要一天学 10 个命令然后全忘掉
3. **记录你自己的常用操作** —— 在笔记里记下你今天学到的操作，明天复习
4. **一个操作如果一周没用上，可能对你不太重要** —— 先放一边，以后再说
5. **遇到重复操作时，想「Vim 有没有更好的方式」** —— 这是你进步的时刻
6. **看别人的配置，但不要照抄** —— 理解每行配置在做什么，再决定要不要
7. **阅读 `:help`** —— 花时间读 `:help` 是投入产出比最高的学习方式

### 10.4 最后的建议

Vim 不是编辑器，是一种 **编辑思维方式**。

当你学会了 Vim，你会发现自己编辑任何文本的方式都变了——你会下意识地思考「单词边界」「段落结构」「操作的最小原子是什么」。

这种思维方式不只在 Vim 中有用。它会让你成为一个更好的程序员，因为它训练你在动手之前先想清楚操作的结构。

**耐心。坚持。三周。**

```vim
" 如果今天你只记住三个命令，记住这三个：
:help                     " 学会使用帮助
i  <Esc>                  " 进入插入，退出插入
.                         " 重复上次操作，Vim 效率的秘密

" 剩下的一切，都会从这三个开始展开。
```
